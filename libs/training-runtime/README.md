# Runtime: прохождение сценария без UI

`@training-observer/runtime` получает готовый сценарий и состояния страницы, возвращает прогресс и новые сообщения. Не
запускает DOM-наблюдение, не записывает сценарии, не читает storage, не показывает Taiga Alerts. Зависит только от
contracts и core/models. Интеграция demo — `projects/demo/src/app/pages/learn`.

## Структура

| Модуль                 | Ответственность                                                         |
| ---------------------- | ----------------------------------------------------------------------- |
| `scenario-runtime.ts`  | координация готовности, переходов и результата                          |
| `field-evaluator.ts`   | сопоставление обязательных полей, выбор исходного/blur значения, оценка |
| `feedback-tracker.ts`  | память сообщённых ошибок и подавление повторов                          |
| `control-matcher.ts`   | детерминированный поиск цели по descriptor                              |
| `training-progress.ts` | выходная модель обновления                                              |

Публичны ScenarioRuntime, TrainingProgress, matchControl/ControlMatch. Остальные классы — детали композиции, не сервисы
Angular и не точки расширения приложения. Начните чтение с update → tryTransition → FieldEvaluator.

## Алгоритм обновления

1. Неготовый экран даёт waiting/blocked. Проблема наблюдения не считается ошибкой ответа.
2. При другом ключе проверить уходящий экран, включая последнее blur-подтверждение.
3. Перейти только на ожидаемый следующий экран, если обязательные поля прошлого выполнены.
4. При входе запомнить baseline подтверждений и исходные значения каждого экземпляра поля.
5. Сопоставить и оценить поля, затем отдать только новые сообщения.
6. Если последний шаг выполнен, вернуть complete. Наблюдение автоматически не останавливается.

Поля одного экрана заполняются в любом порядке. Правильные предзаполненные ответы, включая сумму, засчитываются сразу.
Неправильные исходные значения остаются невыполненными без сообщения. Последующие Input/Number/Select/ComboBox
проверяются после blur. Checkbox/radio проверяются по изменению. Remount/возврат использует новое исходное состояние.
Ожидаемый false проверяется наравне с true.

## Сопоставление

Тип обязателен. Score: стабильный ID 100, label 80, name 40, placeholder 30, контекст 20. Минимум 80, отрыв от второго
кандидата минимум 30. Генерируемые ID не дают сильного балла. Missing/ambiguous блокируют оценку. Одному контролу нельзя
назначить два обязательных ожидания. Ответ и геометрия не входят в score. Это осторожная эвристика, не гарантия
восстановления любой разметки.

## Прогресс и уведомления

TrainingProgress содержит status, номер/число шагов, выполненные/обязательные поля, issue и feedback. Feedback — новые
сообщения конкретного update. Повторять его на последующих рендерах нельзя. Исправление очищает память ошибки, чтобы
новое неверное изменение снова сообщалось. Правильное → неправильное снимает выполненность; optional исключает поле из
проверки. Taiga вызывает Angular-интеграция, runtime хранит только строки сообщений.

## Жизненный цикл и ограничения

Создайте новый runtime на новую попытку, передав результат parseScenario. Конструктор копирует документ. Вызывайте
update при публикациях screen и confirmedControls. Не переиспользуйте подтверждения старого сеанса. Runtime не
восстанавливает неувиденные промежуточные состояния и не различает изменение человеком и backend. Порядок экранов
линейный; общие ветки, группы и произвольные зависимости остаются в плане MVP.
