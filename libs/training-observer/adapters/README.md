# Расширяемая проекция контролов

`@training-observer/core/adapters` — чистая точка входа без Angular и browser API. `projectControls(snapshot, adapters)`
строит логические контролы из сохранённого DOM-графа. По умолчанию доступны native/ARIA правила; правила UI-библиотек
подключаются отдельно.

Адаптер получает `SnapshotReader`, целевой узел, его предков, native kind и `baseCandidate` — результат более низких
слоёв. `match()` возвращает:

- `null` — оставить базовый результат;
- `{status: 'exclude'}` — исключить кандидат, без возврата к native fallback;
- `{status: 'match', kind, hostId?, label?, popup?}` — уточнить контрол.

Более высокий `priority` выполняется позже. Конкурирующие результаты одного приоритета вызывают ошибку с ID адаптеров и
узла. Явный более высокий match может распознать ранее исключённый узел; используйте `baseCandidate`, чтобы уточнять
только уже поддержанные контролы.

Внешний компонент может использовать Taiga внутри: бизнес-адаптер меняет host и подпись, а `base` сохраняет внутренние
слои. Неуказанные host, явная подпись и popup наследуются. Состояния disabled/readOnly/inert/required/invalid
объединяются со всех host; expanded и aria-controls берутся с target, затем из host от внешнего к внутреннему.
`resolveLabel` каждого слоя работает в пределах его собственной обёртки. `excludeCandidate` получает полный список
кандидатов и может проверять цепочку `base`, чтобы служебные части внутреннего компонента оставались его частями.

`locatorHints.testId` использует `data-testid` целевого узла, затем первый непустой атрибут host от внешнего к
внутреннему. Внешняя обёртка без собственного `data-testid` не теряет признак внутреннего поля.

`excludedSubtreeSelectors` задаёт CSS-селекторы служебных поддеревьев. При browser наблюдении они применяются ко всем
путям capture и invalidation; CSS проверяется до запуска сеанса. Чистая проекция работает с уже захваченным графом и не
исполняет CSS-селекторы.

Angular-приложение регистрирует адаптеры один раз через `provideControlAdapters(...adapters)` из
`@training-observer/core`. Локальная регистрация наследует родительскую. Повторная регистрация того же объекта
идемпотентна; разные объекты с одинаковым ID отклоняются. ID `native` зарезервирован. Listener, MutationObserver и
polling остаются в core.

Один контрол пока представляет одно существующее `ControlKind` и DOM-значение. Несколько самостоятельных полей остаются
несколькими контролами; агрегатные значения требуют отдельного контракта записи и проверки.
