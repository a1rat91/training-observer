# Библиотека наблюдения: текущее устройство

`@training-observer/core` читает состояние интерфейса одного документа. Она не знает
процедур, страниц demo, правильных ответов или названий микрофронтов. Учебный runtime
пока не реализован. Существующий `DomHighlighter` — отдельная утилита визуализации,
не обязательная часть наблюдения.

```text
DOM + native properties
  → TrainingObserver / DomObservationSession
  → DomSnapshotBuilder → DomSnapshot
  → проекция и адаптеры → ControlSnapshot[]
  → readScreenState(снимок, контролы, конфигурация интеграции)
  → ScreenState → ScreenVisitTracker
```

Наблюдатель переснимает DOM после мутаций и событий изменения значений; периодическая
сверка обнаруживает изменения свойств без событий. Обновления объединяются. Сравнение
полных снимков подавляет одинаковые публикации, но не является семантическим сравнением
учебных ответов. Журнала кликов нет.

`readScreenState` — чистая функция, которая работает только с готовым снимком и его
проекцией контролов. Интеграция задаёт существующий тег/атрибут корня, источник его ключа
(атрибут или прямой текст) и необязательный признак загрузки. При единственном видимом
корне функция ограничивает контролы его поддеревом. Отсутствие корня/ID и усечение снимка
дают `unavailable`, несколько корней — `ambiguous`, явная загрузка — `loading`.
`ready` означает читаемый экран, а не правильность ответа или полноту каждого контрола.

`ScreenVisitTracker` принадлежит одной сессии интеграции. Новое готовое значение ключа
создаёт посещение; A → B → A — три посещения. Замена DOM при том же ключе обновляет ссылочный
ID узла без нового посещения. Во время неопределённости сохраняется последнее готовое
посещение; оно не выдаётся за текущий экран. `reset()` начинает счёт заново.

Angular-интеграция запускает наблюдение после отрисовки и владеет сервисом через локальный
provider/DestroyRef. Чистые модели и reader не требуют Angular. UI инспектора исключается
из снимка; на контролы целевого приложения учебные маркеры не добавляются.

## Граница demo

HTTP fixture, формы Taiga, кнопки навигации и сохранение ответов относятся исключительно
к `projects/demo`. Форма не импортирует библиотеку. Страница `/record` связывает наблюдатель
с правилами чтения уже существующего ID секции и выводит карточки из `ControlSnapshot`.
Карточки не читают Angular-модель формы. Ожидания и сообщения в них пока не редактируются.

## Что ещё не гарантируется

- ID контролов относятся к живым узлам, а не к полям между разными документами.
- Промежуточные состояния между снимками могут быть потеряны; смена ID не доказывает клик.
- `ready` не снимает ограничения shadow DOM/iframe, redaction и неизвестной selection.
- Источник ключа из URL, отдельного вложенного элемента и политика качества учебной оценки
  ещё требуют расширения контракта интеграции.
- Сохранение сценария, долговечное сопоставление, semantic diff и проверка после blur
  находятся в [плане MVP](docs/snapshot-training-plan.md).

Чистая логика проверяется `npm run test:unit`, реальные формы и жизненный цикл — Playwright.
