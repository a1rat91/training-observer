# Библиотека наблюдения: текущее устройство

`@training-observer/core` читает состояние интерфейса одного документа. Она не знает
процедур, страниц demo, правильных ответов или названий микрофронтов. Базовый учебный runtime проверяет ожидания внутри записанного пути экранов. Существующий `DomHighlighter` — отдельная утилита визуализации,
не обязательная часть наблюдения.

```text
DOM + native properties
  → TrainingObserver / DomObservationSession
  → DomSnapshotBuilder → DomSnapshot
  → проекция и адаптеры → ControlSnapshot[]
  → readScreenState(снимок, контролы, конфигурация интеграции)
  → ScreenState → ScreenVisitTracker
  → StateRecorder + confirmedControls → StateRecording JSON
  → compileScenario → редактор → TrainingScenario JSON
  → ScenarioRuntime + matchControl → progress / feedback
```

Наблюдатель переснимает DOM после мутаций и событий изменения значений; периодическая
сверка обнаруживает изменения свойств без событий. Обновления объединяются. Сравнение
полных снимков подавляет одинаковые публикации, но не является семантическим сравнением
учебных ответов. Журнала кликов нет.

`readScreenState` — чистая функция, которая работает только с готовым снимком и его
проекцией контролов. Интеграция задаёт существующий тег/атрибут корня, источник его ключа
(атрибут или прямой текст) и необязательный признак загрузки. При единственном видимом
корне функция ограничивает контролы его поддеревом. Отсутствие корня/ID и усечение снимка
дают `unavailable`, несколько корней — `ambiguous`, явная загрузка — `loading`.
`ready` означает читаемый экран, а не правильность ответа или полноту каждого контрола.

`ScreenVisitTracker` принадлежит одной сессии интеграции. Новое готовое значение ключа
создаёт посещение; A → B → A — три посещения. Замена DOM при том же ключе обновляет ссылочный
ID узла без нового посещения. Во время неопределённости сохраняется последнее готовое
посещение; оно не выдаётся за текущий экран. `reset()` начинает счёт заново.

Angular-интеграция запускает наблюдение после отрисовки и владеет сервисом через локальный
provider/DestroyRef. Чистые модели и reader не требуют Angular. UI инспектора исключается
из снимка; на контролы целевого приложения учебные маркеры не добавляются.

## Граница demo

HTTP fixture, формы Taiga, кнопки навигации и сохранение ответов относятся исключительно
к `projects/demo`. Форма не импортирует библиотеку. Страница `/record` связывает наблюдатель
с правилами чтения уже существующего ID секции и выводит карточки из `ControlSnapshot`.
Карточки не читают Angular-модель формы. Отдельный редактор сценария задаёт ожидания и сообщения.

## Что ещё не гарантируется

- ID контролов относятся к живым узлам, а не к полям между разными документами.
- Промежуточные состояния между снимками могут быть потеряны; смена ID не доказывает клик.
- `ready` не снимает ограничения shadow DOM/iframe, redaction и неизвестной selection.
- Источник ключа из URL, отдельного вложенного элемента и политика качества учебной оценки
  ещё требуют расширения контракта интеграции.
- Сопоставление по семантическим признакам и оценка ожиданий реализованы в первом приближении;
  расширенная матрица мутаций, semantic diff и ветвление остаются в [плане MVP](docs/snapshot-training-plan.md).

Чистая логика проверяется `npm run test:unit`, реальные формы и жизненный цикл — Playwright.

## Подтверждение значений

TrainingObserver отдельно публикует `confirmedControls`: focusout отмечает выход из Input/Number/Select/ComboBox,
ближайший снимок после обработки события фиксирует значение. Переход в host или явно связанный popup
не считается выходом. Перед возможным удалением поля сохраняется снимок на границе focusout.
Само исчезновение поля, polling или input/change не подтверждают ответ. Неизвестный выбор остаётся
неизвестным; пароль не сохраняется. Это граница подтверждения состояния, а не доказательство
правильности или личного ввода. Сырые снимки продолжают отражать текущий DOM.

## Запись состояний

`StateRecorder` — чистый класс без Angular/DOM/storage. `start` задаёт исходный экран и отсеивает
старые подтверждения; `observe` сначала принимает blur уходящего экрана, затем фиксирует новый экран.
Владение контролами хранится отдельно от текущего DOM. Checkbox/radio/switch записываются при изменении
наблюдаемого значения, поля ввода и выбора — из `confirmedControls`. Loading не создаёт переход,
неизвестное значение/нечитаемый экран создают явный пропуск. `stop` возвращает независимый JSON-документ.
`complete` означает отсутствие замеченных пропусков, а не завершённость учебного сценария.

Документ содержит значения, ключи экранов, номера посещений и locator hints без DOM-графа.
Это заготовка для редактора: hints ещё не обеспечивают долговечное сопоставление в новом документе.
`parseStateRecording` проверяет версию и структуру; старые записи из другой ветки не принимаются.
Хранение в localStorage и ошибки доступа принадлежат demo `RecordingStore`, а не библиотеке.
После рендера обработчика Stop админка вызывает `TrainingObserver.flush()`, который сохраняет
root/options текущей сессии и публикует последнее подтверждение перед остановкой регистратора.

## Сценарий и ученик

`compileScenario` преобразует только полную запись: порядок посещений сохраняется, повторные значения
одного descriptor внутри посещения сводятся к последнему. Поля внутри шага не упорядочены.
`parseScenario` валидирует отдельный версионированный формат перед хранением и запуском.

`matchControl` работает внутри активного экрана. Тип контрола обязателен; баллы дают существующий
негенерируемый ID (100), подпись (80), name (40), placeholder (30), контекст (20). Минимум 80,
разрыв с ближайшим кандидатом минимум 30. При сомнении — missing/ambiguous. Значения, координаты,
CSS-классы и сессионные ID не участвуют. Это консервативная эвристика, а не гарантия self-healing.
Runtime дополнительно запрещает привязку двух обязательных ожиданий к одному контролу.

`ScenarioRuntime` оценивает обязательные поля текущего посещения. Input/number/select/combobox берутся
из подтверждений после blur, checkbox/radio — из текущего состояния. Неизвестные значения блокируют
оценку. Сначала проверяются ожидания уходящего экрана, затем следующий ключ. Неправильный экран
не продвигает индекс; возврат позволяет продолжить. Обратная связь публикуется при изменении ошибки,
а не при каждом scan. Загрузка/неоднозначность — состояния наблюдения, не ошибки ученика.

Сервис хранения сценария и формы редактора принадлежат demo. Learner Angular-компонент создаёт
runtime на посещение страницы, владеет observer и подписками через DestroyRef и показывает сообщения
через Taiga UI 5 `TuiNotificationService` (наследник `TuiAlertService`). Headless runtime не импортирует Taiga.

## Память доказанного выбора ComboBox

`SelectionEvidence` хранит только единственный выбранный вариант, реально наблюдавшийся в полном
снимке связанного открытого popup. Его подпись должна совпадать с отображаемым значением.
При закрытии списка и неизменных control/host/aria-controls/value это доказательство доступно
для подтверждения после blur (`selection.evidence = previous-snapshot`). Сырой `ControlSnapshot`
по-прежнему описывает только текущий DOM, а не историю.

Новый input/reset, изменившееся значение, открытый список без выбора, loading, неизвестная связь,
удаление/замена контрола, усечение снимка и stop/start сбрасывают сохранённое доказательство.
Само совпадение поискового текста с названием одного из вариантов ничего не подтверждает.

Проверка реальной Taiga UI 5.15.0: первый клик закрывает список без наблюдаемого изменения
`aria-selected`; остаётся текст и `aria-expanded=false`. `ng-reflect-model` присутствует в development,
но не является production-контрактом и не читается библиотекой. Если после выбора открыть список
повторно, выбранный вариант доступен снимку и его можно сохранить до blur. Это поддержанный частный
случай, а не решение первого выбора без DOM-доказательства. Для него потребуется отдельный
контракт источника выбранного значения или явно настроенное сравнение отображаемого текста.

## Редактирование журнала

`removeRecordedEvent` — чистое преобразование учебной записи. Оно удаляет строку, перенумеровывает
sequence, сохраняет visit и проверяет оставшиеся границы экранов и неподтверждённые значения.
Оригинал не изменяется. Общий пропуск наблюдения не разрешается удалять как отдельное поле.

История отмены и сохранение принадлежат админке. Авторские изменения черновика привязаны к visit
и descriptor: пересборка меняет исходные значения, сохраняя явные настройки оставшихся полей.
После правки журнала публикация заблокирована до успешной пересборки. Отдельная метаинформация
связывает опубликованный сценарий с точным JSON записи; после reload несовпадение или отсутствие
этой связи тоже требует пересборки. Runtime получает только валидный опубликованный сценарий,
метаинформация редактора в контракт библиотеки не входит.
