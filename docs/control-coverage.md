# Покрытие контролов и следующие шаги

Проверяемая версия — установленная Taiga UI 5.15.0. «DOM» означает наличие
отрисованных узлов и доступных браузеру свойств; это не обещание семантической
поддержки компонента. Матрица описывает семейства контролов, а не весь каталог Taiga.
Дальнейшие адаптеры ограничены **form-контролами**. Tabs, Stepper, Menu, Tree
и другие навигационные компоненты не входят в план. Уже существующий адаптер
кнопок остаётся доступен, в том числе для отправки и сброса формы.

| Семейство | Текущее поведение | Что ещё нужно |
| --- | --- | --- |
| TuiInput, TuiButton, TuiCheckbox | Логические контролы, значения, базовые состояния; реальные браузерные проверки | Варианты оформления и составные шаблоны |
| TuiSelect, TuiComboBox | Выбор, поисковый текст, явно связанный popup; реальные браузерные проверки | Пользовательский content, группы, виртуальные списки, одинаковые подписи |
| TuiInput с произвольным dropdown | Textbox с отдельным popup; без ARIA-связи — unresolved; реальные проверки | Дополнительные варианты содержимого |
| Native select | Выбранные option, value, подписи включая option[label] | Расширенные сценарии multiple и optgroup |
| TuiRadio, TuiSwitch и native-эквиваленты | Отдельные логические типы, подписи, checked; DOM-value Radio; обновление radio-групп между областями | Семантика объектных Angular-значений недоступна из DOM; подробности в [form-контролах](form-controls.md) |
| Slider, Range | DOM и native-свойства, без логического адаптера | Числовое значение, границы, шаг, составные цели действий |
| Date, DateRange, Month, Time | DOM; некоторые текстовые варианты попадают в общий textbox | Семантика даты/диапазона, календарь, mobile/native picker; это пока не поддержка семейства |
| InputNumber, InputPhone | Возможен общий textbox, текст native input | Маска, формат, бизнес-значение, вспомогательные кнопки |
| InputChip, multi-textfield | DOM; редактирующий textbox намеренно исключён | Множественное значение, chips, удаление отдельного элемента |
| Файловые поля и редакторы формы | Доступный DOM; содержимое файла не читается | Отдельные модели и границы возможностей |
| iframe, Shadow DOM | Отметка границы | Отдельный контекст обхода и наблюдения |

## Области микрофронтов

Согласованный маркер: `[data-mf]`, например `<section data-mf="employee-card">`.
Реестр `MicrofrontendObserver` реализован. API и границы независимости описаны
в [наблюдении микрофронтов](microfrontend-observation.md).

1. Области обнаруживаются автоматически; при удалении освобождаются их сессии.
2. Вложенный `[data-mf]` образует отдельную границу. Его внутренности отсутствуют
   в снимке родительского микрофронта.
3. Мутации и события направляются соответствующим областям через общий источник.
   Старый TrainingObserver сохраняет прежнее поведение; для реестра используется
   MicrofrontendObserver с маршрутизацией по владельцу.
4. Внешний popup связан с владельцем через явную DOM-связь. Маркер не заменяет
   `aria-controls`, и положение popup под body не делает его отдельным микрофронтом.
5. Браузерные тесты проверяют замену корня, перенос узлов, вложенные области
   и независимость счётчиков.
   Значение data-mf — имя области, а идентичность экземпляра должна учитывать DOM-узел:
   одинаковые имена могут встречаться несколько раз.

Общие изменения предков, внешние подписи и перекрытия требуют отдельной политики
инвалидации. События прокрутки и декоративного hover по-прежнему не учебные шаги.

## Долг после аудита

Снимки не заменяют журнал действий. После закрепления областей и адаптеров нужен
отдельный регистратор целей click/keyboard/input и результата асинхронного действия.
Координаты и session-local ID не подходят для поиска того же поля у ученика.

Полные обходы и сериализация пока выполняются в главном потоке. Измерения нужны
на нескольких одновременно меняющихся областях с большими списками. Отдельно
остаются пользовательское отображение TuiTextfield content, неполнота при лимитах,
CSS-изменения без мутаций и рекурсивные цепочки popup.
