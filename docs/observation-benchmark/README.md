# Общий цикл наблюдения: первая часть этапа 5

Дата: 2026-09-13. База — `98575d2`; новая версия — рабочий снимок библиотеки, идентифицированный SHA-256 bundle в
`optimized.json`. Это сравнение до/после общего цикла наблюдения; обе версии уже поддерживают несколько областей.
Исторический single-root spike в это сравнение не входит.

## Воспроизведение

```sh
node scripts/observation-benchmark/run.mjs baseline 98575d2
npm run benchmark:observation -- optimized
```

Нужны зависимости проекта и локальный Chrome. Runner собирает библиотеку через esbuild, запускает её в настоящем
document и подставляет локальный HTML через Playwright route. Demo/backend для замера не нужны. Команда с hash читает
исходники через `git show`, не переключая рабочее дерево. Обе команды выполнять последовательно без параллельной сборки
или браузерных тестов. JSON хранит версию Chrome, платформу, hash fixture/bundle и число повторений.

## Fixture и метрики

Шесть случаев: recorder и runtime, каждый с 12 выбранными / 12 соседними controls, 12 / 1200 и двумя выбранными
областями на 120 + 12 controls / 1200 соседними. Это обычные label/input, без зависимости от устройства Taiga UI.
Порядок и содержимое фиксированы; случайная генерация не используется.

После запуска выполняются 12 изменений текста выключенного соседа с паузами 110 мс, 12 input → blur с разными неверными
значениями и два полных remount выбранной области. Runtime проверяет три ожидания; неверные значения сохраняют группу
активной. Синтетические события разрешены только в этом стенде. Recorder должен сохранить ровно 12 действий.

Отдельно считаются querySelectorAll на Element и Document, features, resolve, чтения input.value выбранных/выключенных
областей, активные document listeners, interval и MutationObserver. Счётчики снимаются для запуска, фона, действий и
remount. Инструментация устанавливается только в benchmark bundle/document и снимается перед GC.

Median/p95 — время dispatch input/blur и одного оборота event loop. При 12 попытках p95 соответствует максимальному
образцу. Это **не** полная задержка зачёта успешного действия и не пользовательский SLA. Фоновые паузы включены в
durationMs; время не выдаётся за чистое CPU. Query-счётчик не считает querySelector и не отделяет discovery от
ownership.

После stop и удаления fixture CDP измеряет разность числа DOM nodes относительно пустого документа: сразу после GC и
после 100 мс с повторным GC. Это проверка остатка узлов в данном прогоне, а не доказательство отсутствия утечек во всех
длительных сессиях. Полное сравнение heap retaining paths пока не выполнено.

## Результаты

Одинаковый hash fixture в обоих JSON. Ниже счётчики фоновой фазы: «до → после».

| Режим    | Выбранные / соседние controls | Element querySelectorAll | features    | resolve |
| -------- | ----------------------------- | ------------------------ | ----------- | ------- |
| Recorder | 12 / 12                       | 49 → 36                  | 0 → 0       | 0 → 0   |
| Recorder | 12 / 1200                     | 49 → 36                  | 0 → 0       | 0 → 0   |
| Recorder | 120 + 12 / 1200               | 62 → 36                  | 0 → 0       | 0 → 0   |
| Runtime  | 12 / 12                       | 1924 → 1086              | 900 → 504   | 75 → 42 |
| Runtime  | 12 / 1200                     | 1924 → 1086              | 900 → 504   | 75 → 42 |
| Runtime  | 120 + 12 / 1200               | 18862 → 10881            | 9360 → 5400 | 78 → 45 |

Число фоновых features runtime снизилось на 42–44%. У runtime один interval вместо двух и на один observer меньше. Число
document listeners — 7 независимо от числа областей. После stop во всех случаях обеих версий осталось 0 измеренных
listeners/observers/intervals. Чтений value соседних controls — 0 во всех фазах. Recorder сохранил 12 действий в каждом
случае, включая прогон с remount.

В крупном fixture обе версии сразу после GC показали остаток 6930 DOM nodes; после 100 мс и повторного GC остаток равен
нулю. Во всех шести случаях обеих версий settledNodeDelta = 0. Результат первого GC сохранён в JSON, а не отброшен.

| Runtime fixture | Median, мс, до → после | p95, мс, до → после |
| --------------- | ---------------------- | ------------------- |
| 12 / 12         | 6,5 → 6,8              | 7,8 → 10,0          |
| 12 / 1200       | 14,9 → 15,4            | 21,4 → 19,7         |
| 120 + 12 / 1200 | 130,6 → 131,7          | 135,4 → 134,3       |

Задержка обработки попытки существенно не улучшилась. Большой fixture всё ещё требует около 132 мс; это причина
продолжить этап 5, а не объявлять оптимизацию завершённой. Рост соседнего DOM также влияет на время, хотя его values не
читаются: глобальную работу discovery/ownership предстоит измерить отдельно.

## Ограничения и следующий шаг

Мутации сейчас пересобирают inventory области целиком. Точный dirty-subtree inventory и кэш identity с invalidation
label/ARIA/context ещё предстоят; нельзя пропускать изменения зависимых соседних элементов ради уменьшения счётчиков.
Sampling всех tracked properties сохранён, потому что backend может изменить поле без DOM event.

Далее нужны отдельные измерения discovery/ownership, успешного зачёта действия и длительных циклов mount/unmount. Число
вызовов показывает снижение работы на фиксированном fixture; процент ускорения любого Angular-приложения из него не
следует.

Проверки изменения: 212 core tests, 4 Angular tests, 35 browser tests, сборка пакета и внешний consumer, ESLint
изменённых файлов. Browser tests запускают свежий backend на 4311 через Angular environment replacement; открытая demo
остаётся на 4310. Это устраняет накопление автотестовых сессий в сервере пользователя.
