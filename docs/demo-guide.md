# Как пользоваться demo

Запуск: `npm start`. Откройте http://localhost:4200/.

В demo три страницы: инструкция, запись администратора и тренировка ученика. Исследование locators, benchmark, каталог
компонентов и отдельный маршрут плеера удалены из приложения. Исследовательские результаты и CLI-измерения сохранены в
docs/spike и scripts/spike-*.

## Сначала пройдите готовый пример

На главной нажмите «Попробовать готовый пример». Наблюдение включится само; JSON и кнопка запуска не нужны. Ваш
сохранённый сценарий при этом не заменяется.

1. В поиске выберите «Заявка на обучение».
2. Заполните ФИО: **Анна Смирнова**, рабочую почту: **anna@example.test**, вид обучения: **Внутренний курс**.
3. Нажмите «Продолжить». Выберите курс **Angular**, формат **Онлайн**, включите **Нужен наставник**.
4. Снова «Продолжить», отметьте **Данные проверены**, затем отправьте заявку.

Начните с почты, а не с ФИО: внутри группы порядок свободный. После ввода текста нажимайте Tab. Измените правильное ФИО
на неверное: зачёт исчезнет. Исправьте его и снова выйдите из поля. Подсказки содержат ожидаемые значения.

Слева работает обычное приложение. Справа видны задания и проверка библиотекой. «Доступно» означает, что можно выполнять
задание; «Завершите ввод» — нужно выйти из поля; «Выполнено» — действие проверено; «Значение не совпадает» — нужно
исправить ввод. «Ожидаем подтверждение» означает, что приложение ещё не показало результат перехода.

## Затем запишите свой сценарий

1. Откройте «Запись» и нажмите «Начать запись» **до** выбора процедуры.
2. Пройдите workflow в приложении. Только действия в выбранных областях попадают в журнал. Текст записывается при blur.
3. Нажмите «Остановить запись». Это останавливает сбор событий, но не определяет успех будущего прохождения.
4. В редакторе выберите **последнее действие сценария** из журнала. По умолчанию выбрано последнее записанное действие.
   Если после нужного действия вы сделали лишние действия, выберите более раннее: хвост не войдёт в сценарий.
5. Выберите **результат действия в приложении**: нажмите кнопку выбора, затем, например, заголовок «Заявка принята». Он
   доказывает успех. Сам клик отправки может закончиться ошибкой сервера и не доказывает, что задача выполнена.
6. В «Группы и переходы» отметьте выбор процедуры и каждое «Продолжить». Для каждого выберите поле или результат,
   который должен появиться после перехода. Если записывали «Новая процедура», отметьте и это действие.
7. Создайте черновик. В карточках измените названия групп, задания, подсказки и значения. Необязательные задания и
   зависимости редактируются здесь же. Порядок действий без зависимостей свободный.
8. Нажмите «Сохранить и открыть прохождение». Приложение начнётся заново, наблюдение включится автоматически.

## Свободный порядок и выбор действия

Группа — задания одного контекста, например текущей формы. Автор указывает её границы в «Группы и переходы»: отмечает
записанное действие, которое завершает группу, и выбирает наблюдаемый результат. Это может быть кнопка, выбор варианта
или навигация; механизм не зависит от названия приложения.

В карточке группы видны **«Задания в любом порядке» → «Действие перехода» → «Результат»**. Можно начать с любого
доступного поля группы. Ввод учитывается после blur. Переход засчитывается только после обязательных заданий и появления
указанного результата. Видимые поля следующей группы заранее не засчитываются.

Если нужно открыть справку перед переходом, оставьте этот клик обычным обязательным заданием, не отмечая его как
границу. Для необходимого порядка отдельных заданий раскройте «Выполнить после другого задания». Без зависимостей
порядок свободный. Сложное условие проверки содержимого справки пока задаётся в JSON.

**«Последнее действие сценария»** ограничивает весь журнал, из которого создаётся сценарий. Оно не задаёт
последовательность полей внутри группы. Последний клик становится завершающим переходом автоматически. **«Остановить
запись»** только завершает сбор событий администратора и не считается действием ученика.

Группы выбираются вручную: библиотека не считает каждое изменение DOM новым экраном. Если приложение разрешило уйти
дальше до выполнения заданий, библиотека сообщит об этом, но не заблокирует клик и не вернёт приложение назад.

## Когда нужны дополнительные настройки

- **Настройки записи и диагностика**: какие области наблюдать, сохранять ли значения, скачать исходную запись,
  посмотреть результаты поиска. По умолчанию менять ничего не нужно.
- **Эксперименты с микрофронтами**: перестановка, скрытие и пересоздание областей. Соседние приложения свёрнуты;
  раскройте их, если хотите проверить изоляцию наблюдения.
- **Условия тестового прохождения** в плеере: другая раскладка и сбои сервера. Выберите параметры и начните новую
  процедуру.
- **Дополнительно: JSON и сложные условия**: ветвления и условия, которым пока нет отдельного визуального редактора.
- **Управление тренировкой**: повтор с начала, остановка и импорт другого сценария. «Применить JSON» перезапускает
  только проверку; «Начать заново» перезагружает приложение и тренировку.

Изменение границ групп сбрасывает черновик заданий: создайте его заново перед сохранением. Новая запись заменяет
предыдущую несохранённую запись. Скачайте исходный журнал, если хотите сохранить её до ухода со страницы.
