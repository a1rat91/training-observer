# Границы применимости

Решение этапа 9: conditional go для ограниченного пилота. Ограничения ниже различают недостаток реализации и недостаток
наблюдаемой информации. Увеличение similarity score или ещё один CSS fallback не устраняют второй случай.

## Что нельзя надёжно доказать одним DOM

| Ситуация                                                   | Почему нет достаточного доказательства                                 | Допустимое поведение / необходимое дополнение                                                           |
| ---------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Две одинаковые кнопки без различающих labels/context       | Порядок и положение не определяют сущность                             | Ambiguous, ручная перепривязка только при появлении признаков; не сохранять nth как доказательство      |
| Другая сущность получила прежнее обозначение               | Role/name/attributes/context могут полностью совпасть                  | DOM-only может ошибиться; нужен бизнес-идентификатор и связь с DOM или запрет автоматического зачёта    |
| Повторяющийся экран процедуры                              | Та же форма может относиться к другой стадии/заявке                    | Наблюдаемый контекст либо instance/revision из согласованного сервиса                                   |
| Серверный успех не отражён в интерфейсе                    | Click/исчезновение spinner не подтверждают нужную операцию             | Проверяемый видимый результат либо публичное событие результата; конец графа сам по себе недостаточен   |
| Виртуализация убрала цель                                  | Узла нет; переиспользованный узел может уже представлять другую строку | Ожидать появления и повторно проверять identity; для скрытой сущности нужен контракт списка/ключ строки |
| Изменились язык, текст и бизнес-контекст                   | Исчезла связь старого описания с новым                                 | Новая проверенная привязка/версия сценария, локализованные варианты или бизнес-ID; не угадывать перевод |
| Custom widget скрывает значение                            | Click не раскрывает его внутреннюю модель                              | Adapter к существующему DOM/ARIA-контракту либо разрешённой публичной зависимости                       |
| Canvas, closed shadow DOM, недоступный iframe              | Внутренняя цель/состояние не доступны текущему наблюдателю             | Внешний контракт или no-go для этого шага; визуальное сходство не решает проблему                       |
| Изменение случилось до capture observer или между опросами | Промежуточное намерение/состояние может быть утрачено                  | Показать недостаточность подтверждения, если она обнаружена; гарантии потребуют событийного контракта   |

В benchmark замена на идентичный DOM действительно дала **1 false accept**. Система не смогла распознать её как
broken/ambiguous. Поэтому формулировка «при любой недостаточной уверенности всегда откажемся» недостаточна: если
наблюдаемые признаки ложно совпадают полностью, неопределённость не видна самому алгоритму. Этот случай нельзя закрыть
только дополнительными unit tests или настройкой порога. [Исходные результаты](./benchmark/RESULTS.md).

Same-origin iframe и open shadow DOM потенциально доступны отдельному наблюдателю, но обход границ roots, ретаргетинг
событий и lifecycle iframe в spike не реализованы. Не считать их автоматически поддержанными из-за общего origin.

## Ограничения текущей реализации

| Область        | Что уже есть                                                                                | Что ещё нужно для выбранного реального workflow                                                           |
| -------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Контролы       | Native-backed Taiga UI 4 controls, generic DOM identity, подтверждение owner/value dropdown | Fixtures для иных библиотек; ARIA checkbox/slider/multiselect не получают семантику автоматически         |
| Number/date    | Raw + явно включённые normalizers, выбор по публичным Taiga directives                      | Конфигурация форматов других controls; normalized value не участвует в identity                           |
| Lifecycle      | Observer, property polling 100 мс, generation token, stop/restart                           | Общий scheduler/индекс при необходимости, измерение нагрузки и кратких переходов                          |
| Вместимость    | Recorder останавливается на лимитах; resolver ограничивает пул                              | Сейчас до 1000 actions / 5000 states, resolver maxCandidates 2000; длительные реальные сеансы не измерены |
| Identity       | Typed locators, проверка конфликтов, scope и near tie                                       | Контрольные наборы реального приложения; калибровка вероятности не проводилась                            |
| Маршруты       | Явная пара `/spike/record` → `/spike/learn`, pathname                                       | Query/hash не включены; определить, где они являются частью бизнес-контекста                              |
| Authoring      | Linear draft, JSON editor, импорт записи, ручные branches/optional/conditions               | UI редактирования и нормализация нескольких input commits, проверка всех веток автором                    |
| Условия        | Value/visible/pathname и all/any, unknown отдельно от false                                 | Нет общего языка бизнес-предикатов, исторических переменных или HTTP-result условий                       |
| Состояние шага | Current committed value переживает удаление поля его обработчиком                           | Значения прежних экранов не являются автоматически доступной историей для будущих веток                   |
| Progress       | Текущее прохождение в памяти                                                                | Server persistence, идентификация попытки, resume с повторной проверкой контекста                         |
| MFE            | Две demo-страницы рядом с одним компонентом плеера                                          | Реальная отдельная сборка, shared deps, injector/overlay/style isolation и remount tests                  |
| Диагностика    | Resolution evidence, состояния, отдельные rrweb probes                                      | Политика хранения, расследование реальных отказов, контроль объёма snapshots                              |

`isTrusted` и generation token помогают связывать действия с наблюдаемым пользователем в проверенном браузере; они не
являются защитой от фальсификации аттестации со стороны владельца браузера. Client-side completion не следует
использовать как доверенное серверное доказательство обязательного обучения без отдельной модели доверия.

## Как трактовать ошибки и ожидания

Отсутствующая сейчас цель не обязательно сломана: backend мог ещё не прислать поле. Runtime показывает ожидание,
повторяет resolve после изменений и применяет timeout. Ambiguous не исправляется переходом к следующему кандидату по
позиции. Disabled-кандидат тоже учитывается как конкурент, чтобы недоступность не разрешала identity tie.

Неверное значение оставляет текущий шаг. State update без подходящего действия не засчитывается. 422/retry проверены по
появлению нужного DOM, а не по анализу HTTP runtime-слоем. Поздние события старого поколения не продвигают новый шаг, но
поздний ответ backend может изменить сам плеер: training observer не отменяет чужую операцию.

Исчезновение цели само по себе не всегда доказывает completion: оно может быть вызвано reset, навигацией или ошибкой.
Автор обязан выбирать условие, отличающее успех от этих случаев. Строгий JSON-валидатор проверяет типы и ссылки, но не
смысл задания. Признак «следующее поле видно» в автоматически созданном черновике может уже быть истинным до клика;
такой сценарий должен быть исправлен до публикации.

## Пределы измерений

Статическая матрица использует новый документ с сериализованным Taiga DOM; это не 17 живых Angular redesigns. Два
независимых браузерных workflow проверяют реальные append/replace, 422, portal и reset. Структурные перестановки
сохранённых labels не моделируют весь спектр изменений реального приложения. 28 вариантов целей — не 28 разных
библиотечных компонентов. Набор мал и зависим; split не заменяет испытаний на целевом приложении.

Задержки median/p95 относятся к отдельным вызовам в локальном Chrome, не к полной задержке действия ученика,
продолжительному сеансу или нагрузке двух независимых Angular MFE. Готовые locators замерены через Playwright round
trip, resolver — внутри страницы: скоростное превосходство из этих чисел не следует. [Методика](./benchmark.md).

## Условия принятия решения для целевого плеера

Можно начинать пилот, если обязательные цели различимы, значения поддержанных controls наблюдаемы, успех каждого
обязательного перехода имеет проверяемый признак, а продукт допускает остановку и исправление сценария при ambiguity.
Нужно проверить те же свойства на настоящих формах, включая reset, повторы экранов, обе ветки и новые версии UI.

Если хотя бы один обязательный шаг не наблюдаем, сначала определить доступную shared dependency или другой уже
существующий публичный контракт. Даже наличие shared DI не гарантирует доступ к требуемому факту. Если контракт
недоступен и отказ/ручная проверка неприемлемы, DOM-only MVP для этого workflow — no-go. Это ограничение постановки, а
не повод маскировать догадку термином self-healing.
