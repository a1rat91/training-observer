# ElementResolver v2 — этап 6

Реализация: `libs/element-spike/src/resolution/`. Общий сбор признаков recorder/resolver:
`libs/element-spike/src/dom/identity.ts`. Старый `src/resolver.ts` относится к черновому контракту v1 и не используется
новой страницей. Вход нового resolver — descriptor v2 после проверки recording/scenario JSON.

## Диагностика в demo

На `/spike/record` запишите заполнение ФИО и остановите запись. В настройках плеера выберите другое расположение,
создайте новую процедуру и нажмите **«Проверить поиск»** в панели записи. Проверяются только цели записанных действий.
Результаты раскрываются в JSON: статус, попытки locators, scores и evidence кандидатов. Resolver возвращает живой
Element отдельно; панель хранит только сериализуемый report.

После сброса процедуры поле ФИО отсутствует и поиск возвращает `broken`. Это диагноз **текущего DOM в момент проверки**,
не окончательная поломка учебного шага. Ожидание полей, timeout, прохождение и completion реализованы в
[runtime этапа 7](./scenario-runtime.md). После изменения DOM результат нужно проверить снова; автоматически
кэшированный Element не используется.

## Алгоритм

1. Проверить версию descriptor, алгоритм fingerprint и pathname. Другая оболочка разрешается только явной направленной
   парой `routePairs: [{recorded: '/spike/record', current: '/spike/learn'}]`. Глобального игнорирования маршрута нет.
2. Собрать контролы внутри переданного root. Не брать чужой training UI; исключить отключённые от document, недоступные
   по accessibility/CSS, inert и содержимое закрытых details (кроме summary). При превышении лимита пула вернуть
   `unsupported`, не выбирать из усечённого набора.
3. Проверить семантический scope. Записанные именованные контексты — границы: исчезновение/смена сотрудника, формы или
   группы не исправляются автоматически. Wrappers и перенос в безымянный контейнер разрешены, если контекст сохраняется.
   `contextRequired` без сохранённого контекста означает недостаточные данные.
4. Проверить semantic locators, затем CSS; сохранить count и outcome каждой попытки. Invalid CSS даёт `rejected`.
   Recorded uniqueness не переносится на новый DOM.
5. Проверить identity всех конкурентов, включая при единственном совпадении locator. Роли и типы input должны быть
   совместимы; уже существовавшие `name`/`href`, которые теперь указывают другое значение, — конфликт identity.
6. Учитывать accessibleName/label/text/placeholder как одну коррелированную группу. Берётся первый доступный основной
   признак в этом порядке, а не максимум, который мог бы скрыть противоречивый accessibleName. Similarity — Dice по
   множествам нормализованных слов (NFC, whitespace, lowercase), детерминированный эвристический score. Изменившаяся
   строка с тем же множеством слов (порядок/повторы/пунктуация), изменившиеся числовые токены и явные отрицания
   `не/нет/без/not/no/without` не принимаются как мелкая правка. Это защитные лексические проверки, не полноценное
   понимание смысла и не универсальный анализ отрицаний во всех языках.
7. Проверить абсолютный порог и отрыв от второго кандидата. Disabled-конкурент участвует в неоднозначности: одна
   активная кнопка среди одинаковых не становится доказанно правильной. Сам disabled winner не возвращается готовой
   целью.
8. Если уникальный locator указывает на проверенного победителя: `semantic` либо `css-verified`; если все locators
   сломались, но fingerprint даёт достаточное доказательство: `similarity`. Иначе `broken`/`ambiguous` без Element и без
   selectedCandidateId. Порядок DOM используется только для ID диагностических кандидатов, никогда для выбора при tie.

Ранжирование проверяет конкурентов даже при semantic match, поэтому у текущего spike нет быстрого пути, который
возвращал бы первое уникальное совпадение без проверки остального пула.

## Предварительные параметры

| Параметр        | Значение                                    | Значение для решения                          |
| --------------- | ------------------------------------------- | --------------------------------------------- |
| Naming          | 0.7                                         | Одна группа, не три голоса от label/name/text |
| Context         | 0.2                                         | Полный сохранённый контекст совпал            |
| Attributes      | 0.1                                         | Доля совпавших независимых `name`/`href`      |
| Score threshold | 0.9                                         | Минимальный нормированный score               |
| Margin          | 0.12                                        | Минимальный отрыв от второго кандидата        |
| Naming gate     | 0.9; 0.75 при точных независимых attributes | Отказ от слишком слабого сходства             |
| Max candidates  | 2000                                        | Отказ до рассмотрения усечённого пула         |

Знаменатель score включает только имеющиеся в descriptor группы. Роль/type, tag, CSS, позиция, classes, generated ID и
общие атрибуты вроде `autocomplete` не прибавляют баллы identity. Без содержательного имени либо точного независимого
атрибута цель не принимается, даже если её CSS уникален. Безымянная кнопка «?» не восстанавливается.

Пороги — консервативные стартовые параметры, **не измеренная вероятность и не итоговая калибровка**. Их нужно проверять
на отдельном наборе и benchmark этапа 8. Совпадение всех наблюдаемых признаков не доказывает неизменность скрытой
бизнес-сущности.

## Покрытие и ограничения

Unit tests: wrappers/reorder/classes/reparenting, icon/span, recreated input, native → ARIA button, semantic и CSS
fallback, fuzzy recovery, near-tie, повторяющиеся контексты и удалённый сотрудник, уникальный ложный CSS, role/type/name
conflicts, недоступные/disabled цели, route pairs, ограничение пула и сериализуемый детерминированный report. Browser
test проверяет реальное пересоздание формы Taiga UI после остановки записи и отказ после удаления формы. Это не полный
20–30-element benchmark и не проверка сценарного runtime.

Изменение именованного контекста может дать отказ даже при фактически той же цели. Это намеренная граница текущего
spike. Полная смена подписей/языка, одинаковые сущности с одинаковым DOM, исчезнувшие признаки, виртуализация и скрытые
бизнес-ID без интеграции надёжно не восстанавливаются. Пул поддерживает тот же набор контролов, что recorder;
произвольные canvas/closed shadow DOM и custom widgets не становятся поддержанными от наличия similarity.

Для поиска доступны видимые readOnly поля: resolver решает identity, а применимость конкретного input/select действия и
ожидание enabled/readOnly состояния должен проверять runtime. DOM-only snapshot не гарантирует, что элемент останется
подключённым после возврата `resolve`; перед использованием binding требуется повторная проверка.

Проверки 2026-09-11: 105 unit tests (31 resolver + 74 contracts/recorder), общий прогон 16 browser tests, TypeScript,
ESLint и Angular development build прошли. После добавления лексических защит повторены все unit tests и сборка;
отдельный повторный браузерный тест пересоздания формы также прошёл. Полный benchmark не заменяется этими числами.
