# ElementRecorder — этап 5

Реализация: `libs/element-spike/src/recording/`. Контракт: `training-recording`, version 2. Отдельная страница
администратора: **`/spike/record`**, пункт меню «Запись процедуры». Она монтирует существующий `ProcedurePageComponent`
рядом с панелью записи. `/spike/procedure` остаётся самостоятельным плеером; `/spike/learn` добавлен на этапе 7 —
[прохождение и подготовка сценария](./scenario-runtime.md). Это demo композиции в одном document, ещё не сборка
отдельного MFE.

## Как проверить руками

1. `npm start`, открыть http://localhost:4200/spike/record.
2. При необходимости выбрать другое расположение/поведение сервера в настройках плеера **до** начала записи.
3. Выбрать, сохранять ли значения, нажать «Начать запись», затем «Новая процедура» в плеере.
4. Заполнить ФИО, рабочую почту и вид обучения; пройти появляющиеся формы до «Заявка принята».
5. Справа появляются semantic actions с именами полей и значениями. `false`, `true`, пустая строка и пропущенное по
   политике значение различаются. Ввод объединяется до change/blur либо 400 мс без ввода.
6. Нажать «Остановить запись» → «Скачать запись». JSON проверяется строгим валидатором перед скачиванием. Новая запись
   заменяет предыдущую; уход с маршрута уничтожает recorder. Автосохранения пока нет.

JSON содержит дескрипторы, действия, наблюдаемые состояния и диагностику. Это **запись**, ещё не учебный сценарий: для
редактирования инструкций/условий и прохождения запись преобразуется в Scenario v2.
[Подготовка сценария и runtime ученика](./scenario-runtime.md).

## Что делает recorder

- Capture listeners в document и `composedPath()` находят интерактивного предка icon/span. Наблюдение ограничено
  переданным DOM-root плеера; собственная панель не попадает в запись. Плеер не получает tracking-атрибутов.
- При первом обнаружении сохраняются признаки и проверенные locator candidates. Перед действием сравниваются текущие
  признаки и pathname. Изменившийся контекст того же узла создаёт новый descriptor, старые записи не переписываются.
- `MutationObserver` обнаруживает добавление/удаление/замену контролов и изменения атрибутов. Отдельный опрос DOM
  properties раз в 100 мс видит `.value`/`.checked`, которые не вызывают MutationObserver. State хранится только при
  изменении. Ни setters, ни History API не патчатся; pathname наблюдается отдельно.
- Действия отделены от snapshots и программных обновлений. По умолчанию синтетические события не являются действиями.
  Учитывается и каскад `element.click()` → native change, где вторичное событие может иметь `isTrusted: true`.
- Input bursts, change/blur, idle и IME имеют отдельный жизненный цикл. Незавершённый IME при stop/detach даёт
  диагностику, а не подтверждённый ввод. Значение снимается также после синхронных обработчиков текущего события, чтобы
  сохранить форматирование Taiga. Позднее серверное обновление не подменяет уже зафиксированный пользовательский ввод.
- Checkbox/radio/native select дают `select`. Для Taiga Select сначала нужен единственный владелец popup через уже
  существующие `aria-controls`/`aria-owns`. Имя option снимается до удаления popup, затем проверяется изменение
  отображаемого значения владельца и его совпадение с выбранной option. Поддержаны pointer и клавиатурный выбор.
  Generated ID используется только для текущей связи popup с владельцем, не сохраняется как locator.
- Подтверждение выбора обрабатывается перед следующим действием. Если подтвердить выбор не удалось, выдаётся
  диагностика: выбор не вставляется задним числом и порядок действий не угадывается.
- Значения берутся из публичного DOM, без Angular FormControl/DI, payload HTTP и ключей схемы. Разрешённые нормализаторы
  распознают поля по публичным директивам Taiga: число с десятичной запятой и дата `DD.MM.YYYY`. Raw сохраняется
  отдельно; неполные и невозможные значения не получают normalized.
- Password/file и autocomplete current-password/new-password/one-time-code редактируются политикой `redact`. Режим
  `omit` исключает значения из actions/states, но не удаляет произвольный текст интерфейса из identity features.
- Start идемпотентен во время записи; stop отключает listeners, MutationObserver, interval, уведомления и ссылки на
  узлы. Generation guard отменяет отложенные callbacks прошлой записи. Ограничены объём, число
  descriptors/actions/states; при достижении лимита запись останавливается с диагностикой, не обрезает события молча.

## Проверки

```sh
npm run test:spike
npx playwright test tests/recording.spec.ts tests/procedure.spec.ts tests/research.spec.ts
npx tsc -p libs/element-spike/tsconfig.json --noEmit
NX_DAEMON=false NX_ISOLATE_PLUGINS=false npx nx build demo --configuration=development
```

Unit tests проверяют объединение ввода, IME, pre-removal capture, detached state, программные события и property
updates, политики значений, единственного/двойного владельца popup, неподтверждённый выбор, порядок быстрых действий,
изменение контекста, навигацию, очистку/restart, предел записи и нормализацию.

Browser tests используют настоящий Chrome, Taiga UI 4.98.0 и HTTP-плеер. JSON скачивается через UI и проходит строгий
`parseRecording`. Проверяются точные 12 действий внутренней ветки в обоих layout, значения внешней ветки с серверной
422, выбор с клавиатуры, omit и programmatic property update. `acceptUntrustedEvents` включается только в некоторых unit
fixtures; browser panel его не включает. Тесты плеера и исследования остаются регрессионными проверками.

Результат 2026-09-11: 74 unit-теста контрактов/recorder, 9 API-тестов и 15 browser tests прошли; TypeScript, Angular
development build, ESLint и Stylelint также прошли. В первом общем browser-прогоне существующий тест плеера однократно
получил ошибку Chrome `Network.getResponseBody`; повторный полный прогон прошёл без изменения этого теста.

Это проверка **записи**, не процент восстановления элементов. Resolver и 20–30-element benchmark ещё предстоят.

## Границы доказанного

- Опрос properties пропускает переходы, которые возникли и исчезли между отсчётами. Для полных синхронных изменений без
  пользовательских событий нужна интеграция с целевым приложением; recorder такой гарантии не заявляет.
- Подтверждение dropdown по отображаемому тексту не доказывает скрытый бизнес-ID. Одинаковые option labels, custom
  presentation, отсутствие/дублирование ownership требуют адаптера либо отказа. Новый ввод до подтверждения (таймаут 1
  с) оставляет запись с диагностикой. Повторный выбор уже выбранного значения не является изменением.
- Проверен текстовый ввод даты Taiga InputDate. Calendar popup, autocomplete search, multiselect и другие custom
  controls не считаются подтверждённо поддержанными по аналогии с Select. Нераспознаваемый option даёт диагностику;
  произвольные события canvas/closed shadow DOM могут быть вообще невидимы наблюдателю.
- Источник произвольного программного обновления нельзя определить по одному DOM. State не означает действие, нажатие
  «Продолжить» не означает успешный backend commit. У записи ещё нет completion runtime.
- Pathname опрашивается: мгновенные промежуточные переходы могут быть пропущены; query/hash не входят в контракт
  navigation v2. Разные оболочки record/learn требуют явного соответствия scope на этапе resolver/runtime.
- Дескрипторы создаются и для наблюдаемых контролов без действий. Это диагностическая запись с ограничением 500
  descriptors, 1000 actions, 5000 states и приблизительно 900 тысяч символов полезной нагрузки. Итоговый JSON
  дополнительно проверяется общими ограничениями контракта. Производительность на больших формах пока не измерена.
- `rrweb` остаётся отдельным диагностическим инструментом исследовательской страницы; он не служит источником
  подтверждённых semantic actions и не устраняет перечисленные неопределённости.
