# Зависимость от UI-библиотеки

Ядро не зависит от Angular DI и устройства Taiga UI. Оно видит публичный DOM и события; имя npm-пакета контрола не
участвует в идентификации. Но «увидеть клик», «прочитать значение» и «доказать semantic select» — разные возможности.

| Контрол                                                                   | Что работает сейчас                                                                | Где граница                                                                                                                                                      |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Обычный input/textarea внутри любого Angular-компонента                   | Input/change/blur, value, labels/ARIA, properties                                  | Контрол должен реально предоставлять такой DOM и наблюдаемые события                                                                                             |
| Native checkbox/radio/select                                              | Checked/selected labels, semantic select                                           | Это не произвольный div, внешне похожий на checkbox                                                                                                              |
| button, ссылка, summary, `role="button"`                                  | Click и семантические признаки; icon/span внутри                                   | Внутреннюю бизнес-операцию клик не доказывает                                                                                                                    |
| `contenteditable="true"`                                                  | Текстовый ввод и raw textContent                                                   | Сложная модель rich text не сериализуется как документ                                                                                                           |
| Taiga Select или другой совместимый dropdown                              | Option → единственный owner через aria-controls/owns → подтверждённое DOM-значение | Проверена Taiga 4.98.0; другой пакет надо проверить контрактными fixtures. Владелец должен иметь читаемое значение; совпадения по внешнему сходству недостаточно |
| Taiga InputNumber / InputDate                                             | Raw плюс явно разрешённая нормализация                                             | Выбор нормализатора пока Taiga-specific: публичные `tuiinputnumber`/`tuiinputdate`                                                                               |
| Другой number/date с input                                                | Raw ввод записывается                                                              | Собственный формат не получит Taiga-нормализацию автоматически                                                                                                   |
| Custom `div role="checkbox"`, slider, сложный multiselect, calendar popup | Полная семантика изменения значения пока не реализована                            | Одного ARIA role недостаточно для текущего recorder; нужен дополнительный DOM adapter и тесты                                                                    |
| Canvas, closed shadow DOM, cross-origin iframe                            | Поддержка не заявлена                                                              | Нужен доступный внешний контракт/интеграция; внутреннее состояние может быть принципиально недоступно                                                            |

`src/dom/identity.ts` содержит общие DOM-признаки, используемые и recorder, и resolver. В нём нет Taiga directives,
Angular imports и generated IDs для поиска. `src/recording/dom.ts` пока содержит маленькую привязку публичных Taiga
атрибутов к нормализаторам значений. Resolver не импортирует этот модуль и не использует normalized/raw value как
identity.

Для новой библиотеки нужно сначала определить её **наблюдаемый контракт** и воспроизвести события в браузере. Если
контракт совпал с уже поддержанным — новый adapter не нужен. Иначе adapter должен читать существующий DOM/ARIA,
обосновывать owner и подтверждение значения; при неоднозначности выдавать отказ. Tracking-маркеры в приложении ради
такого adapter не добавляются. Интеграция через уже shared DI — отдельный явно помеченный режим, а не DOM-only
результат.

Универсальный plugin API для adapters ещё не реализован: до этого нужна матрица реальных контролов из целевого
приложения. Неизвестные options с недоказанным owner дают диагностику; невозможно обещать диагностику каждого невидимого
события в произвольном custom widget. Обнаруженный и подсвеченный элемент ещё не означает, что его значение корректно
записывается.
