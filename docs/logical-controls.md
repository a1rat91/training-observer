# Логические контролы: первый набор адаптеров

`DomSnapshot` описывает DOM-узлы. `ControlSnapshot` описывает один распознанный
контрол: тип, подпись, значение, доступность и признаки для будущего поиска.

```ts
const observer = inject(TrainingObserver);
observer.start(root);

observer.snapshot();        // исходный DOM-снимок
observer.controls();        // прежний список потенциально интерактивных DOM-узлов
observer.logicalControls(); // новый список ControlSnapshot
```

Новый список — computed signal от опубликованного снимка. Нормализация не
устанавливает слушатели, не читает живой DOM и не вызывает повторный пересчёт.
Можно отдельно вызвать `inject(ControlSnapshotBuilder).build(snapshot)` для
ранее сохранённого DOM-снимка. Результат содержит только JSON-совместимые данные.

## Поддержка

| Тип | Native HTML | Taiga UI 5.15 |
| --- | --- | --- |
| `textbox` | input text/search/email/tel/url/password, textarea | текстовый input/textarea в обычном `tui-textfield`, маркер `tuiInput` |
| `button` | button, input button/submit/reset | button с `tuiButton` / `tuiIconButton` |
| `checkbox` | input checkbox | input checkbox с `tuiCheckbox` |
| `radio` | input radio | input radio с `tuiRadio` |
| `switch` | input checkbox с role=switch или атрибутом switch | input checkbox с `tuiSwitch` |
| `select` | select / option | input с `tuiSelect`, связанный dropdown |
| `combobox` | — | input с `tuiComboBox`, поиск и связанный dropdown |

Адаптер Taiga UI проверяется первым, затем native-адаптер. Сведения берутся из
DOM-тегов и атрибутов, без обращения к Angular injector, экземплярам компонентов
или приватным полям Taiga UI. Стенд содержит настоящие TuiInput, TuiButton и
TuiCheckbox с привязкой к форме для проверки пользовательского взаимодействия.

Числовые/календарные контролы, contenteditable,
ARIA-контролы без native-элемента и редактор `tui-textfield[multi]` не входят в
этот набор. Их DOM остаётся в исходном снимке. Вложенный простой контрол сложного
виджета может быть распознан отдельно; полноценная семантика виджета ещё не описана.

Динамические dropdown, варианты, загрузка и границы достоверности выбранного значения
описаны в [наблюдении за Select и ComboBox](dropdown-observation.md).
Radio и Switch, включая подписи и межобластные radio-группы, описаны
в [наблюдении form-контролов](form-controls.md).

## Объединение DOM

Поле получает `targetNodeId` своего input/textarea и `hostNodeId` обёртки
`tui-textfield`. `memberNodeIds` связывает поле с захваченной разметкой: обёрткой,
текстом, подписью и известными служебными элементами.

Кнопка очистки `[tuiButtonX]` в поддержанном поле и disabled `aria-hidden` input
с классом `t-filler` входят в представление поля, не создавая второй контрол.
Самостоятельные кнопки внутри поля сохраняются отдельно. Labels сами по себе не
становятся логическими контролами. Поля с одинаковой подписью не объединяются.

`memberNodeIds` пока не является алгоритмом разрешения цели события. Например,
shared label может относиться к нескольким элементам. При записи действий
потребуется отдельно различать ввод в поле и нажатие на его кнопку очистки.

## Состояние и подпись

Значение, checked/indeterminate и остальные native-свойства берутся из состояния
целевого DOM-узла. Disabled/readOnly/inert/required/invalid учитывают также хост.
Геометрия и признаки видимости относятся к целевому элементу и моменту снимка.
`pointerActionable` не гарантирует успешное бизнес-действие.

Основная подпись берётся из DOM-анализатора (aria-labelledby, aria-label,
associated labels, текст кнопки и другие приближённые признаки). Для Taiga UI
есть fallback на единственный захваченный floating label `[tuiLabel]`.
При нескольких неподписанных labels адаптер не выбирает один наугад.

Password остаётся с `state.redacted: true`, без значения. Для checkbox сохраняются
checked/indeterminate, а техническое значение вроде `on` не используется.
Скрытые и заблокированные контролы сохраняются в модели.

## Идентичность и будущий поиск

`id` вида `control:n17` привязан к живому native DOM-узлу в текущей сессии.
Изменение значения сохраняет этот ID; замена узла создаёт новый. Он не подходит
для поиска того же контрола у ученика или после перезагрузки.

`locatorHints` содержит тип, подпись, тег, роль, input type, id/name/data-testid,
placeholder и доступный в снимке контекст form/fieldset/section/dialog.
Значение, координаты, классы оформления и структурный DOM-путь в hints не включены.
Отсутствующие признаки остаются отсутствующими, внешние атрибуты добавлять не нужно.

Это набор свидетельств, а не готовый уникальный локатор: DOM id может генерироваться,
а подписи и имена — повторяться. Следующий шаг — сопоставление кандидатов с явным
результатом «найден / не найден / неоднозначно», без угадывания по первому совпадению.

## Ограничения и проверки

Проекция наследует ограничения и неполноту исходного снимка; проверяйте
`snapshot.stats.truncated`. Ссылки ведут только на узлы этого снимка. iframe и
Shadow DOM по-прежнему отмечаются как границы.

Нормализация пока пересчитывается целиком при публикации DOM-снимка. Индексация
и измерения на больших страницах — отдельная работа.

Браузерные тесты проверяют настоящие Taiga UI контролы и очистку поля, native
fallback, текущие значения/доступность, замену и удаление узлов, совпадающие
подписи, сохранность самостоятельных кнопок, редактирование паролей и лимиты обхода.
