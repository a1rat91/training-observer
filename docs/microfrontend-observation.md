# Независимое наблюдение микрофронтов

Маркер области — `[data-mf]`. Его значение служит именем, а не уникальным ключом:

```html
<section data-mf="profile">
    <input aria-label="Имя" />
    <section data-mf="address"><input aria-label="Город" /></section>
</section>
<section data-mf="profile"><input aria-label="Другой профиль" /></section>
```

Здесь три независимо наблюдаемых экземпляра. Внутренности address отсутствуют
в снимке profile. Пустое значение data-mf тоже допустимо. Один и тот же живой
DOM-элемент сохраняет ID в пределах экземпляра сервиса; замена новым элементом
создаёт новый ID даже при прежнем имени. ID не предназначен для сопоставления
интерфейсов админа и ученика.

## API

```ts
import {inject} from '@angular/core';
import {MicrofrontendObserver} from '@training-observer/core';

const observer = inject(MicrofrontendObserver);
// После рендера. По умолчанию искать корни во всём document.body.
observer.start();
// Или ограничить обнаружение контейнером:
observer.start(container, {batchDelayMs: 50, propertyCheckIntervalMs: 500});

observer.areas();       // readonly signal со снимками всех зарегистрированных областей
observer.isObserving();
observer.refresh(id);   // запланировать обновление одной области
observer.refresh();     // запланировать обновление всех областей
observer.stop();        // снять слушатели/таймеры, сохранить сериализованные результаты
observer.clear();       // также удалить результаты
```

Предоставляйте сервис в `providers` встраиваемого компонента: его `DestroyRef`
освободит ресурсы. При `providedIn: 'root'` сервис живёт до уничтожения приложения.
Повторный start заменяет работающую сессию. Некорректные настройки проверяются
до остановки прежней сессии. После stop изменения областей не отслеживаются;
следующий start заново обнаруживает текущие корни.

Каждая запись содержит `id`, `name`, `parentId`, `snapshot`, `logicalControls`,
`scanCount`, `revision`, `error`. DOM-объекты в публичный результат не входят.
Удаление корня или data-mf удаляет запись из текущего реестра. Ошибка обхода одной
области останавливает её сессию и сохраняет ошибку, не останавливая остальные;
для повторного запуска после ошибки нужен start.

`boundarySelector` принудительно равен `[data-mf]`. `ignoreSelector` исключает
и снимки, и обнаружение областей: вложенные корни внутри интерфейса наблюдателя
не регистрируются. На соседние компоненты библиотека ничего не записывает.

## Как направляются изменения

На весь реестр создаются один MutationObserver, один комплект делегированных
обработчиков и один таймер сверки native-свойств. Каждая область имеет собственное
окно объединения событий и строит только свой снимок. Обычный `TrainingObserver`
по-прежнему доступен для прежнего режима снимка страницы.

| Изменение | Какие области обновляются |
| --- | --- |
| Ввод, текст, атрибуты, добавление обычного контрола | Владелец ближайшего data-mf |
| Содержимое вложенного микрофронта | Вложенная область |
| Перенос обычного узла между областями | Прежний и новый владельцы |
| Добавление/удаление data-mf на существующем контейнере | Реестр и затронутый родитель |
| Внешний popup с явным aria-controls | Область ссылающегося контрола |
| Изменение внешней подписи aria-labelledby/aria-describedby | Области, ссылающиеся на подпись |
| Атрибуты общих предков, стили stylesheet, resize окна | Зависимые области, возможно несколько |
| Посторонний блок вне областей | Пересчёт снимков не запускается |
| Scroll и декоративные hover-переходы | Не запускают пересчёт сами по себе |

Реестр проверяет появление/исчезновение корней при структурных и атрибутных
мутациях. Это поиск областей без геометрического обхода, а не пересборка всех
снимков. Обновления внутри исключённого инспектора отфильтрованы.

Первое открытие Taiga dropdown может добавить общие `<style>` в `<head>` и потому
пересчитать все области. Последующие открытия без новых общих стилей обновляют
только владельца popup. Завершение загрузки внешнего stylesheet также обновляет
области: CSS может примениться позже мутации, добавившей `<link>`.

Для позднего появления popup запоминаются и ещё не разрешённые aria-controls
открытых контролов. После вставки подходящего корня обновится владелец. Поля
в захваченном popup также проходят сверку native-свойств. Popup под другим
`[data-mf]` не включается повторно во внешний снимок. Рекурсивные цепочки popup
по-прежнему не обходятся; ID ссылок должны быть уникальны в документе.

## Ограничение геометрии

Изменение одного микрофронта может сдвинуть соседний через layout, а внешний
несвязанный overlay — перекрыть его. Ради независимости такой косвенный эффект
не запускает полный обход соседей. Их координаты и hit-test относятся к последнему
снимку; перед подсветкой используйте `refresh(id)` и дождитесь обновления счётчика.
Семантика учебного действия не должна зависеть от устаревшей геометрии.

Внешние associated labels через HTML for без aria-labelledby пока не внесены
в таблицу зависимостей. CSSOM без DOM-мутаций и изменения layout без событий
по-прежнему требуют явного refresh. Это не гарантия знания всей видимой страницы.

Обход каждой области пока полный. Сверка свойств может искать элементы внутри
вложенных корней, но их состояния проверяются только у владельца. Лимиты относятся
к снимку одной области, а не к суммарной стоимости работы реестра. Нагрузочные
замеры на сотнях областей остаются следующим отдельным этапом.

## Стенд

Запустить `npm run start:parser` и открыть `/microfrontends` (ссылка «Микрофронты»
на главной). Видны profile, вложенный address и employment с настоящим Taiga Select.
Карточки показывают отдельные счётчики, родителя и контролы. Кнопки добавляют
второй profile, удаляют области, останавливают реестр и обновляют снимки.
