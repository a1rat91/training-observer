# Form-контролы: Radio, Switch и InputNumber

Следующие адаптеры библиотеки предназначены для полей формы. На этом этапе добавлены `radio`, `switch` и `number`;
версия Taiga UI — 4.98.0.

| Контрол        | DOM-признак                                                        | Состояние                                    |
| -------------- | ------------------------------------------------------------------ | -------------------------------------------- |
| TuiRadio       | `input[type=radio][tuiRadio]`                                      | checked, DOM-value, доступность и валидация  |
| TuiSwitch      | `input[type=checkbox][tuiSwitch][role=switch]`                     | checked, доступность и валидация             |
| Native Radio   | `input[type=radio]` без противоречащей роли                        | Аналогично TuiRadio                          |
| Native Switch  | `input[type=checkbox][role=switch]` либо `[switch]` без явной роли | Аналогично TuiSwitch                         |
| TuiInputNumber | `input[tuiInputNumber]` с типом text/number и совместимой ролью    | Точная строка value, доступность и валидация |
| Native Number  | `input[type=number]` без роли или с role=spinbutton                | Строка value и браузерная валидация          |

Каждый radio-вариант — отдельный `ControlSnapshot`. Поле `state.checked` говорит, выбран ли вариант, `state.value`
содержит значение **DOM input**. При Angular `[value]="object"` браузерное value может не содержать объект или
уникальный ключ. Библиотека не читает Angular ControlValueAccessor, FormControl и приватные поля Taiga и не выдаёт
DOM-строку за бизнес-значение. Имя и контекст группы остаются в `locatorHints.name` и `locatorHints.context`; единый
объект radio-группы пока не создаётся, особенно при неполном снимке или разных областях наблюдения.

Switch имеет двоичное состояние `checked`. Native value вроде `on` не становится значением переключателя;
`indeterminate` не переносится в логический Switch. У Checkbox поддержка `indeterminate` сохраняется.

## Подписи обязательны в примерах

Каждый Radio имеет собственный label, Switch — подпись переключателя. Библиотека читает `aria-labelledby`, `aria-label`,
связанные `label[for]` и оборачивающие `label`. Связанные HTML-label входят в `memberNodeIds`. `legend` описывает группу
в `locatorHints.context`, а не заменяет подпись варианта.

```html
<fieldset>
  <legend>Способ доставки</legend>
  <label>
    <input
      type="radio"
      name="delivery"
      value="email"
    />
    Электронная почта
  </label>
  <label>
    <input
      type="radio"
      name="delivery"
      value="sms"
    />
    SMS
  </label>
</fieldset>
<label for="auto-save">Автосохранение</label>
<input
  id="auto-save"
  type="checkbox"
  role="switch"
/>
```

На внешней странице может встретиться контрол без подписи. Он остаётся в снимке с пустым `label`: парсер не придумывает
подпись из name, value или legend и не скрывает такой контрол. Непустая корректная подпись должна быть обеспечена
исходным интерфейсом; это не повод требовать доработки соседнего микрофронта для самого наблюдения.

## Изменения и radio-группы

`input`/`change` фиксируют выбор мышью и клавиатурой. Периодическая сверка native свойств обнаруживает программные
изменения checked без события.

Браузер снимает checked с прежнего варианта без отдельного change на нём. Поэтому при input/change нового radio
`MicrofrontendObserver` обновляет также области, в которых находятся его native-партнёры: совпадают непустой name,
DOM-дерево и **form owner**. Учитывается и внешняя форма через `form="id"`. Одинаковые name в разных формах не
объединяются. У неназванных radio общей группы нет.

Событие reset внешней формы также направляется в области её полей. Эти сценарии работают при
`propertyCheckIntervalMs: 0`. Изменения native-свойств без события, включая программные изменения состава группы, при
отключённой сверке требуют явного refresh; это прежнее ограничение наблюдения за DOM-свойствами.

## Проверки

В разделе `/controls` раскрыть «Radio и Switch». Там находятся настоящие TuiRadio/TuiSwitch с Angular Forms, подписями и
disabled-вариантом.

`tests/form-controls.spec.ts` проверяет распознавание, подписи и их изменения, выбор мышью/клавиатурой, silent property
writes, disabled/inert, двоичный Switch, radio-группу в разных микрофронтах и reset через внешнюю форму без polling.

## InputNumber

`kind: 'number'` отличает числовое поле от общего textbox. Значение `state.value` остаётся **строкой DOM без
преобразований**: сохраняются разделители, префикс, постфикс, знак, пустая строка и промежуточный ввод. Например,
`1 250,5 ₽` не превращается в `1250.5`. Это предотвращает угадывание формата и потерю точности для bigint.
`inputmode="numeric"` сам по себе не делает поле числовым: так могут вводиться номера договоров с ведущими нулями. ARIA
spinbutton без native input и числовые поля внутри `tui-textfield[multi]` пока не получают этот адаптер.

`locatorHints.role` сохраняет фактическую роль: masked input Taiga без явной роли остаётся textbox, обычный input number
имеет implicit role spinbutton. Тип контрола и роль в accessibility tree — разные признаки.

Поле получает host своего `tui-textfield` и связанные подписи. Cleaner входит в `memberNodeIds`, как у текстовых полей.
Кнопки `+`/`−` остаются отдельными логическими кнопками с собственными label и disabled: нажатие и результат изменения
числа впоследствии нужно будет различать при записи действий. Их label не является уникальным локатором при нескольких
числовых полях. Явно связанный через ARIA dropdown (`aria-haspopup`, `aria-expanded`, `aria-controls`) попадает в
`popup`, без объявления его списком выбора или доказательством выбранного значения.

Обычный ввод обнаруживается через события, изменения value без событий — через сверку native-свойств. Это относится и к
обновлениям из Angular, включая кнопки шага, если конкретный компонент не отправляет native input/change. При отключении
сверки такие изменения без мутаций потребуют refresh. Scroll/hover не добавлены в источники событий.

В Taiga 4.98 настройки `[min]`, `[max]`, `[step]`, number format и value transformer могут оставаться в директивах и DI,
без отражения в HTML-атрибутах. Парсер не читает Angular-модель и не обещает восстановить эти ограничения либо значение
после transformer. Атрибуты min/max/step, если присутствуют, доступны в исходном DOM-снимке; отдельной модели числовых
ограничений пока нет. `invalid` отражает только наблюдаемую браузерную/ARIA-валидацию, а не все ошибки Angular
FormControl. Для проверки ученика семантическое сравнение `1 000,00` и `1000` ещё предстоит реализовать; на текущем шаге
библиотека сохраняет наблюдаемый текст поля.

В `/controls` раскрыть «InputNumber». Стенд содержит реальные поля Taiga с валютой, другими разделителями и native input
для целого за пределами Number.MAX_SAFE_INTEGER и обычный HTML input number. `tests/number-controls.spec.ts` проверяет
точность строки, подписи, ввод/шаг/очистку, доступность кнопок на границах, native-валидацию, изменения свойств без
событий, распознавание и явно связанный popup. Taiga UI 4 InputNumber принимает `number`: атрибут `bigint` здесь не
поддерживается. Поэтому проверка большого целого использует native input и чтение `.value` как строки.

Следующие семейства: Slider/Range, дата/время, поля с несколькими значениями. Для них понадобятся собственные модели
значения и составных контролов.
