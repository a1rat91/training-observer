# Подсветка DOM-узлов

`DomHighlighter` — отдельный Angular-сервис для диагностической подсветки. Он не
создаёт учебные события и не вызывает пересборку снимка. В demo `/controls`
доступны подсветка логических контролов, всех потенциально интерактивных DOM-узлов
и отдельного контрола из таблицы. Номера соответствуют порядку в выбранном списке;
это не постоянные идентификаторы для учебного сценария.

```ts
import {inject} from '@angular/core';
import {DomHighlighter, TrainingObserver} from '@training-observer/core';

const observer = inject(TrainingObserver);
const highlighter = inject(DomHighlighter);
const snapshot = observer.capture(document.body);

highlighter.show(snapshot); // snapshot.interactiveIds
const ids = observer.logicalControls().map((control) => control.targetNodeId);
highlighter.show(snapshot, ids); // логические контролы
highlighter.show(snapshot, ids, ids[0]); // один, с номером из общего списка
highlighter.clear();
```

Для независимого жизненного цикла добавьте `DomHighlighter` в `providers` компонента.
При уничтожении Angular injector слой и animation loop освобождаются. Повторный
`show()` заменяет предыдущую подсветку данного экземпляра. Если снимки обновляются,
вызывайте `show()` из `effect`, как в `ObserverPanelComponent`: сам highlighter не
подписывается на наблюдателя и не добавляет новые цели без нового вызова.

## Связь с DOM и отрисовка

`DomSnapshotBuilder` хранит для исходного объекта снимка соответствие ID →
`WeakRef<Node>`. `resolveElement(snapshot, id)` возвращает только подключённый
элемент того же документа. Снимки не удерживают удалённые DOM-деревья через эти
ссылки. После сериализации/десериализации привязок нет; восстановление цели
учебного сценария между загрузками страницы — отдельная задача.

Как в [buildDomTree.js](https://github.com/nanobrowser/nanobrowser/blob/master/chrome-extension/public/buildDomTree.js),
для каждого `getClientRects()` рисуется цветная рамка и ставится номер возле
первого видимого прямоугольника. У слоя `pointer-events: none`, поэтому можно
продолжать работать с формой. Скрытые, удалённые и находящиеся вне viewport цели
не рисуются. Число рамок обновляется, в том числе при переносе текста.

Пока подсветка включена, один `requestAnimationFrame` вне Angular zone читает
живую геометрию выбранных целей. DOM рамок меняется только при изменении координат.
Это учитывает скролл вложенных контейнеров, resize и смещение раскладки без
пересборки снимков. Стоимость чтения геометрии растёт с количеством выбранных
целей; для постоянной подсветки предпочтителен один выбранный контрол.

Слой размещён в Shadow DOM служебного элемента с зарезервированным атрибутом
`data-training-observer-ui`. Обход DOM и оба режима наблюдения исключают его
независимо от пользовательского `ignoreSelector`, включая добавление и удаление
слоя. Shadow DOM изолирует внутренние стили и мутации рамок от страницы.

## Границы первого этапа

Подсвечиваются элементы light DOM, доступные в живом снимке, включая уже
связанные внешние popup. Текстовые узлы, внутренности iframe и чужих Shadow DOM
пока не поддержаны. Рамки показывают геометрию элемента, не вычисляют полигон
видимой части после перекрытия соседями или обрезания всеми overflow-предками.
Native popup системного select не является DOM-элементом. Слой в body не
гарантирует отображение поверх browser top layer (`dialog`, popover); transform
на предках слоя также может менять его систему координат.
