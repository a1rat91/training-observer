# Покрытие контролов и следующие шаги

Проверяемая версия — установленная Taiga UI 4.98.0. «DOM» означает наличие отрисованных узлов и доступных браузеру
свойств; это не обещание семантической поддержки компонента. Матрица описывает семейства контролов, а не весь каталог
Taiga. Дальнейшие адаптеры ограничены **form-контролами**. Tabs, Stepper, Menu, Tree и другие навигационные компоненты
не входят в план. Уже существующий адаптер кнопок остаётся доступен, в том числе для отправки и сброса формы.

| Семейство                                | Текущее поведение                                                                                             | Что ещё нужно                                                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| TuiTextfield, TuiButton, TuiCheckbox     | Логические контролы, значения, базовые состояния; реальные браузерные проверки                                | Варианты оформления и составные шаблоны                                                                                                |
| TuiSelect, TuiComboBox                   | Выбор, поисковый текст, явно связанный popup; реальные браузерные проверки                                    | Пользовательский content, группы, виртуальные списки, одинаковые подписи                                                               |

## Области микрофронтов

По умолчанию корни находятся по `microfrontend > *`, например
`<microfrontend><employee-card>…</employee-card></microfrontend>`. Имя области — DOM-тег корневого компонента.
`MicrofrontendObserver.observe(selectors)` принимает другие существующие селекторы приложения без добавления маркеров.
API и границы независимости описаны в [наблюдении микрофронтов](microfrontend-observation.md).

1. Области обнаруживаются автоматически; при удалении освобождаются их сессии.
2. Вложенный корень, совпавший с селектором, образует отдельную границу. Его внутренности отсутствуют в снимке родителя.
3. Мутации и события направляются соответствующим областям через общий источник. TrainingObserver наблюдает одну
   область; для реестра используется MicrofrontendObserver с маршрутизацией по владельцу.
4. Внешний popup связан с владельцем через явную DOM-связь. Граница не заменяет `aria-controls`, и положение popup под
   body не делает его отдельным микрофронтом.
5. Идентичность экземпляра учитывает DOM-узел: одинаковые имена могут встречаться несколько раз. Замена корня создаёт
   новый ID.

Общие изменения предков, внешние подписи и перекрытия требуют отдельной политики инвалидации. События прокрутки и
декоративного hover по-прежнему не учебные шаги.

## Долг после аудита

Снимки не заменяют журнал действий. Однако по [решению для ветки lib от 14 сентября](../roadmap.md) текущий MVP
проверяет состояния и ID экранов; отдельный регистратор click/keyboard/input не является обязательным следующим этапом.
Он понадобится, только если потребуется доказательство конкретных действий. Координаты и session-local ID не подходят
для поиска того же поля у ученика.

Полные обходы и сериализация пока выполняются в главном потоке. Измерения нужны на нескольких одновременно меняющихся
областях с большими списками. Отдельно остаются пользовательское отображение TuiTextfield content, неполнота при
лимитах, CSS-изменения без мутаций и рекурсивные цепочки popup.
