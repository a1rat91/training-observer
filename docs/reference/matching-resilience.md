# Устойчивость сопоставления: воспроизводимое измерение

Проверено 15 сентября 2026 года в headless Chrome через Playwright. Набор: 30 случаев разметки, включая 8 настоящих
контролов Taiga UI 4 и 22 обычных HTML-контрола. Это 30 случаев, а не 30 различных типов API.

## Что измерено

Исходная проекция распознала **26 из 30 (86,7%)**. Native input типов date, time, month и week не создают логический
ControlSnapshot: они учитываются как неподдерживаемые, а не исчезают из отчёта.

Для 26 распознанных элементов проверены 14 вариантов нового документа — **364 попытки сопоставления**. Все 260 попыток в
10 вариантах с сохранённым смыслом завершились правильно (100% среди распознанных, 86,7% от полного набора с учётом
отсутствующей поддержки четырёх типов). В четырёх намеренно проблемных вариантах получилось 100 правильных совпадений и
четыре безопасных отказа. **Ложных совпадений в итоговом прогоне: 0.** Это результат фиксированного набора, а не
статистическая оценка надёжности на произвольном приложении.

## Независимый эталон

Тест открывает страницу /controls и использует действующие capture и проекцию библиотеки. Снимок берётся вручную,
наблюдение остановлено: измеряется восстановление элемента, а не временная доставка событий. Исходные locatorHints
сохраняются в процессе теста. Для каждого варианта открывается новый document. Matcher получает исходный descriptor и
все текущие ControlSnapshot, включая посторонние контролы страницы.

Эталон — сохранённые тестом ссылки на DOM-элементы нового документа, находящиеся вне наблюдаемого DOM. В текущем снимке
тест сопоставляет path с живой ссылкой для проверки ответа. XPath здесь только проверяет результат конкретного capture:
он не переносится между документами и не используется matcher. Дополнительные DOM-маркеры, ожидаемые ответы и эталонные
ссылки в поиск не передаются.

Состав: Taiga Input, Select, ComboBox, Checkbox, два Radio, Switch и InputNumber; HTML
email/tel/search/url/date/time/month/week/number, textarea, внешний label/for, aria-labelledby, aria-label, placeholder,
readonly, disabled, одиночный и множественный select, checkbox, radio, текстовая кнопка и кнопка с aria-label. Точные
fixture и мутации находятся в [matching-cases.ts](../../tests/fixtures/matching-cases.ts) и
[matching-resilience.spec.ts](../../tests/matching-resilience.spec.ts).

## Найденные и исправленные дефекты

- **Подмена ID.** До исправления новое поле с прежним ID, но другой подписью давало ложное совпадение. Теперь
  противоречащая непустая подпись обнуляет оценку этого кандидата. Другой подходящий кандидат по-прежнему может быть
  найден по семантике. Порог и отрыв не понижены.
- **Декоративная иконка.** Текст aria-hidden-потомка попадал в подпись действия. Capture теперь исключает такое
  поддерево из текста кнопки/ссылки/действия, сохраняя приоритет явных ARIA-подписей. Это узкое исправление, не
  реализация полного алгоритма Accessible Name.

## Границы и оставшаяся работа

- Календарные HTML-контролы date/time/month/week ещё не поддержаны логической проекцией.
- Одновременное исчезновение подписи и ID не оставляет достаточного доказательства идентичности.
- Дубликаты с одинаковыми признаками требуют контекста или явного уточнения; выбор первого недопустим.
- Переименование поля при сохранении ID неотличимо от передачи ID другому полю. При противоречии подписей теперь
  возвращается отказ вместо прежнего совпадения. Это намеренное ужесточение поведения.
- Если другой элемент повторяет все наблюдаемые признаки старого, DOM не доказывает его бизнес-идентичность.
- Проверены готовые состояния, а не все промежуточные изменения, IME, асинхронная загрузка popup или несколько
  одновременно меняющихся областей. Это отдельная приёмка. Нагрузку и производительность этот тест не измеряет.
- Поведение нестандартных ARIA-виджетов и полное вычисление доступного имени требуют отдельного покрытия.

## Повторить

`npm run test:matching` запускает стенд и проверяет 26 правильных совпадений для каждого варианта с сохранённым смыслом,
отсутствие ложных совпадений и отказы для проблемных случаев. JSON с результатом каждого элемента сохраняется как
Playwright attachment `test-results/matching-resilience-*/matching-resilience.json`. Там же перечислены нераспознанные
исходные элементы. Отчёт выше фиксирует этот прогон; при расширении поддержки контролов обновляйте ожидания теста и
отчёт вместе.
