# Оставшаяся работа

Текущее состояние: работает цикл запись → редактирование → публикация → прохождение. Есть удаление и отмена событий,
карточки ожиданий с сообщениями ошибок/успеха, свободный порядок полей внутри экрана, проверка переходов, blur,
предзаполненные ответы и начальные checkbox/radio, включая false. Core, contracts, recording и runtime разделены;
архитектура, инструкции и README пакетов актуальны.

Ниже — незавершённые блоки. Это не обещание, что все они входят в ближайший релиз.

1. **Контракт интеграции — частично готов.** Добавлены ID из отдельного видимого потомка и положительный признак
   готовности корня (`identity.element`, `ready`). Остались URL, внешние источники ID и несколько независимых областей.
   Наблюдение нескольких областей по произвольным селекторам уже есть в core; здесь речь о сопоставлении их экранов со
   сценарием обучения. Уточнить политики сохранения чувствительных данных и пропусков наблюдения. Reader читает атрибут
   или прямой текст корня либо выбранного потомка.
2. **Устойчивое сопоставление.** Проверить 20–30 видов контролов в новом документе после wrappers, reorder, classes,
   вложенности и перемещения. Измерять верные/ложные совпадения, ambiguous и missing отдельно. Расширить семантические
   изменения для появления/исчезновения полей. Процент надёжности пока не измерен.
3. **Расширения админки.** Карточки ожиданий и обратная связь выполнены: отдельная карточка поля с типом, контекстом,
   ожидаемым значением, сообщениями ошибки/успеха и предпросмотром; сообщения доходят до Taiga Alerts ученика без
   повторов. **Группы вариантов отложены по решению пользователя:** создание, безопасный выбор состава, в том числе во
   время записи, и настройка групповой обратной связи. **Импорт/экспорт через UI выполнен:** скачивание публикации,
   проверка файла и сводка перед заменой, редактирование без местного журнала. Остались зависимости/ветки/условия
   завершения и pause/resume с честными разрывами.
4. **Расширения прохождения.** Допустимые ветки и зависимости. Оценка групп и обратная связь для них отложены вместе с
   группами в админке. Механизм должен опираться на наблюдаемый результат. Клики без изменения состояния требуют
   отдельного источника подтверждения: одни снимки их не доказывают.
5. **Приёмка на разных интерфейсах.** Помимо demo проверить независимые DOM-структуры, динамические поля, соседние MF,
   порталы, быстрые переходы, IME, remount и неполные снимки. Выпустить воспроизводимый отчёт и перечень случаев,
   требующих интеграции с приложением.
6. **Измерение и оптимизация — последними.** Использовать нагрузочный стенд: стоимость capture, projection и matching,
   задержки p50/p95, память, влияние соседних MF. Оптимизировать только измеренные проблемы и повторно проверить
   функциональные гарантии.

ComboBox в текущей тренировке сравнивается по видимому тексту после blur. Доказательство выбора backend-объекта не
является незавершённым исправлением этого правила; это отдельная возможная интеграция.
