# Select и ComboBox: динамические dropdown

В стенде «Отдел» теперь настоящий `input[tuiSelect]` Taiga UI 5.15.
«Сотрудник» — `input[tuiComboBox]` с фильтрацией и имитацией ответа через 400 мс.
Это поведение demo; библиотека не читает его signals, таймеры или Angular-модель.

## Как проверить в интерфейсе

1. Запустить `npm run start:parser` и открыть http://127.0.0.1:4201.
2. Найти в инспекторе карточку «Отдел». Изначально: текст «Разработка», список
   закрыт, отрисованных вариантов нет.
3. Открыть «Отдел»: появятся три варианта, «Разработка» помечена выбранной,
   «Продажи» заблокированы. Связь с dropdown видна как `aria-controls`.
4. Выбрать «Поддержка»: значение обновится, список закроется. Повторное открытие
   создаст новые DOM-узлы вариантов при прежнем ID контрола.
5. Ввести «Анна» в «Сотрудник»: сначала «Загрузка» и текст «Поиск…», затем
   отрисованный вариант «Анна Смирнова». Несуществующий запрос даст пустой результат.
6. Выбрать вариант или закрыть список Escape. Инспектор отразит текущее состояние.

## Связь поля с порталом

В реальном DOM Taiga UI закрытый input уже имеет:

```html
<input tuiSelect aria-expanded="false" aria-controls="tui_…" aria-haspopup="listbox">
```

Dropdown при этом ещё отсутствует. Открытие меняет `aria-expanded` на `true` и
создаёт вне формы `tui-dropdown` с соответствующим `id` и `role="listbox"`.
Варианты имеют `role="option"`, `aria-selected`; недоступные варианты — disabled.
Связь создана самой Taiga UI, добавлять атрибуты в соседние микрофронты не требуется.

`MutationObserver` уже слушает весь document и замечает создание портала,
замену текста/вариантов, ARIA-атрибуты и закрытие. `DomSnapshotBuilder` теперь
расширяет scoped-снимок явно связанными внешними listbox:

- ссылки берутся только у захваченных открытых контролов с `aria-haspopup="listbox"`;
- внешние корни записываются в `relatedRootIds`, с `parentId: null`;
- основной `rootId` остаётся корнем формы; ложная DOM-вложенность не создаётся;
- при обходе body уже вложенный портал не дублируется;
- пересекающиеся внешние корни обходятся один раз;
- `ignoreSelector` и общий лимит `maxNodes` действуют и для порталов;
- `maxDepth` считается от каждого корня, а общая статистика охватывает весь снимок.

Если портал ещё не появился, исключён или не помещается в снимок, адаптер возвращает
`unresolved`. Он не выбирает ближайший listbox и не использует фокус как доказательство
принадлежности. Сбор вложенных порталов рекурсивно по цепочке ссылок пока не реализован.

## Модель

В `ControlSnapshot` добавлены `kind: 'select' | 'combobox'` и `choice`:

- `displayValue` — текущий видимый текст поля;
- `selection` — наблюдаемый выбор либо `unknown`;
- `popup.status` — `closed`, `open`, `unresolved` или `native`;
- `popup.referencedIds` / `rootNodeIds` — ARIA-связь и узлы данного снимка;
- `popup.busy` — `aria-busy`, если он есть; при отсутствии признака `null`;
- `popup.options` — захваченные варианты: подпись, disabled, selected и HTML value,
  только если оно действительно присутствует в атрибуте;
- `popup.text` — текст списка, включая сообщение загрузки/пустого результата.

У Taiga UI `input[tuiSelect]` текст представляет выбранное отображаемое значение.
У combobox текст может быть незавершённым поиском. Поэтому без `aria-selected`
в текущих вариантах закрытый combobox имеет `selection.status: 'unknown'`, даже
если в нём виден текст. Значение `state.value` в этом случае — текст input,
а не обещание, что Angular FormControl содержит выбранный объект.

Мы не читаем `ng-reflect-*`, внутренние объекты и сервисы приложения. Если в DOM
видна подпись «Поддержка», но нет бизнес-ключа `departmentId`, этот ключ неизвестен.

Обычный HTML select тоже нормализуется: native `value`, выбранные option,
подписи и disabled. Его системное всплывающее окно не является DOM-порталом;
статус `native` отражает именно это ограничение.

## Что считается известным

Виртуальный список может содержать в DOM только несколько строк. До открытия
и загрузки вариантов их состав неизвестен. `popup.options` описывает только
захваченный DOM, не полный справочник. `snapshot.stats.truncated` отдельно
предупреждает об ограничении самого захвата.

Добавление/удаление вариантов при прокрутке вызывает обновление через мутации.
Служебные ползунки Taiga UI по-прежнему исключены. Декоративные hover-переходы
цветов и теней не становятся причиной полного пересчёта.

## Дальше: запись действия выбора

Здесь реализовано наблюдение состояния, не журнал действий. Снимки объединяются
по времени и могут пропустить очень краткий промежуточный список.
Будущий регистратор должен в capture-фазе click/keydown зафиксировать цель
выбора и её связь с полем **до** удаления dropdown; затем сопоставить результат
с последующим состоянием. Нельзя пытаться восстановить нажатый вариант только
по DOM после закрытия. Клавиатурный выбор должен поддерживаться наравне с мышью.

Тесты проверяют настоящие Select/ComboBox Taiga UI, задержку результатов,
пустую выдачу, выбор мышью и клавиатурой, Escape, повторное создание портала,
посторонний listbox, отсутствие связи, ограничения захвата и native select.
