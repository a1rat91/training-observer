# Training Observer

Библиотека без UI для наблюдения действий в существующем приложении и проверки учебных сценариев. DOM-цели описываются
несколькими признаками; при неоднозначности библиотека отказывается от выбора. Runtime не использует LLM, а целевым
формам не нужны специальные tracking-атрибуты.

[Архитектура библиотеки](ARCHITECTURE.md) · [План разработки](docs/implementation-plan.md) ·
[API и подключение](libs/training-observer/README.md)

## Структура

- `libs/training-observer` — пакет `@training-observer/core`: контракты, запись, resolver, runtime и registry областей.
- `@training-observer/core/angular` — отдельный entry point с DI, signals и lifecycle. Компонентов UI в пакете нет.
- `projects/demo` — внешнее Angular-приложение для проверки библиотеки: админка, режим ученика и динамические формы
  Taiga UI 4.
- `tests` — браузерные проверки интеграции и поведения контролов.
- `docs/spike` и `scripts/spike-*` — архив исследования и воспроизводимые измерительные инструменты. Старые реализации
  ядра удалены.

Сейчас используются Angular 19.2 и Taiga UI 4.98; обновление Angular не требуется.

## Сборка и проверки

```sh
npm ci
npm run build:library
npm run test:package
npm test
npx playwright test tests/areas.spec.ts tests/microfrontends.spec.ts tests/recording.spec.ts tests/learning.spec.ts
```

Пакет собирается в `dist/training-observer`. `test:package` проверяет импорт готового пакета в Node без DOM, закрытые
внутренние пути и типы обоих entry points без workspace aliases. Публикация в npm не выполняется.

## Demo

```sh
npm start
```

Команда запускает Angular на порту 4200 и тестовый HTTP backend на 4310. Откройте
[главную страницу](http://localhost:4200/) и нажмите **«Попробовать готовый пример»**. Наблюдение включается
автоматически; сохранённый авторский сценарий при этом не заменяется. [Пошаговая инструкция](docs/demo-guide.md)
содержит значения полей, объяснение статусов и запись собственного сценария.

| Маршрут   | Назначение                                           |
| --------- | ---------------------------------------------------- |
| `/`       | Как пользоваться: готовый пример и инструкция        |
| `/record` | Админка: запись, группы и переходы, редактор заданий |
| `/learn`  | Тренировка: автоматическая проверка и подсказки      |

На записи сначала остановите сбор событий, затем выберите последнее действие сценария и наблюдаемый результат успеха.
Отметьте действия перехода между группами и их результаты. В карточках редактируются задания, подсказки, ожидаемые
значения, optional и зависимости. Независимые задания активной группы выполняются в любом порядке; следующий экран не
засчитывается заранее. Последний клик автоматически становится завершающим переходом.

Настройки наблюдаемых областей, импорт/экспорт и диагностика свёрнуты. Соседние MF и эксперименты с раскладкой доступны
для проверки изоляции и изменений DOM. Исследовательские страницы, каталог компонентов и автономный маршрут плеера
удалены. Старые `/spike/record` и `/spike/learn` перенаправляются на новые маршруты; прочие старые страницы — на
инструкцию.

## Текущее состояние

Demo использует публичный API библиотеки; сборка пакета и Angular-обвязка проверяются отдельно. Scenario v4 поддерживает
группы, свободный порядок, requires, optional и проверяемые переходы. Ввод подтверждается после blur, повторное
редактирование снимает зачёт. Старые Scenario v2/v3 сохраняют последовательный интерпретатор; их импорт не меняет
порядок автоматически. Сложные условия и ветки пока редактируются в JSON. Общий ownership portals и измеряемая
оптимизация остаются в плане.

[Результаты исследования](docs/spike/benchmark.md) и [ограничения DOM-only подхода](docs/spike/limitations.md) остаются
основаниями архитектурных решений. Исторические отчёты содержат пути и хэши исходников на момент измерения.
