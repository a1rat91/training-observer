# Training Observer

Nx workspace на Angular 19: приложения в `projects/`, библиотеки в `libs/`.

**Текущий план ветки `lib`: [обучение по состояниям и ID экранов](docs/snapshot-training-plan.md).**
Проверяем значения и достижение экранов; универсальная запись кликов не входит в этот MVP.

## Проекты

| Проект | Назначение |
| --- | --- |
| `libs/training-observer` | Angular-библиотека `@training-observer/core`: снимок DOM, native-состояния контролов и автоматическое наблюдение. |
| `projects/demo` | Все примеры и стенды: контролы, живой инспектор, микрофронты и нагрузочные сценарии. |

Angular 19.2.25, CLI 19.2.27, Nx 20.8.4, Taiga UI 5.15.0, TypeScript 5.8.3.
Приложение использует standalone-компоненты, Angular Router и Less.

## Запуск

Требуется Node.js 22 (версия в `.nvmrc`).

```sh
nvm use
npm ci
npm start
```

Demo: [http://127.0.0.1:4200](http://127.0.0.1:4200).
На странице «Контролы» инспектор запускается автоматически. Измените форму или добавьте поле — снимок
обновится сам. Доступны остановка, повторный запуск и ручной снимок. В настройках
можно выбрать всю страницу, задержку объединения событий и интервал сверки свойств.
Кнопки закрытия/открытия инспектора проверяют жизненный цикл его Angular-компонента.

Разделы переключаются через общее меню в шапке:

| Маршрут | Содержимое |
| --- | --- |
| `/record` | Запись подтверждённых значений и переходов, журнал и сохранение |
| `/controls` | Контролы Taiga UI и HTML, динамические dropdown, инспектор состояния |
| `/learn` | Автоматическая проверка по сохранённому сценарию и Taiga Alerts при ошибках |

Корневой адрес перенаправляет на `/record`. Страницы загружаются лениво;
наблюдатели освобождаются при переходе в другой раздел. Общее меню исключено
из наблюдения. Страницы находятся в `projects/demo/src/app/pages`, инспектор —
в `shared/observer-panel`. Библиотека от приложения demo не зависит.

Подсветка контролов и DOM-узлов: [API и устройство слоя](docs/node-highlighting.md).

### Как записать пример

1. Откройте «Запись» и дождитесь формы.
2. Нажмите «Начать запись». Заполните поля в любом порядке; выйдите из Input/Select/ComboBox, чтобы подтвердить значение.
3. Нажимайте «Далее» и продолжайте заполнение. Журнал показывает значения и посещения экранов.
4. Нажмите «Завершить запись». Последний blur будет обработан, журнал сохранится в localStorage этого браузера.
5. Перезагрузите страницу: завершённая запись останется. JSON можно скопировать из раскрываемого блока.

До старта и после завершения новые наблюдения не добавляются в журнал. Новая запись заменяет сохранённую
только после завершения; незавершённый сеанс при уходе со страницы не сохраняется. Это запись состояний
для редактора; исполняемый сценарий сохраняется отдельно после настройки ожиданий. Предзаполненные поля без нового подтверждения
не становятся ожиданиями автоматически. Неизвестные значения и пропуски отмечаются в журнале.
В частности, закрытый Taiga ComboBox может показывать текст без доказательства выбора: такую строку
регистратор помечает неподтверждённой, а не сохраняет поисковый текст как выбранный вариант.
Если выбранный вариант был виден в снимке открытого списка, библиотека сохраняет это доказательство
до blur, даже когда список уже закрыт. Новый ввод, изменение текста, связи popup или экземпляра
контрола сбрасывает доказательство. Сырые снимки при этом не переписываются.

В меню только три страницы. Проверки MF и нагрузки доступны внутри «Контролы» → «Дополнительные проверки»
(`/controls?fixture=microfrontends`, `/controls?fixture=load`). Отдельных страниц `/microfrontends` и `/load` нет.

### Как запустить тренировку

1. Для первого прогона запишите Фамилию и Подразделение, нажмите «Далее», затем завершите запись.
2. Раскройте «Настроить тренировку» → «Создать ожидания из записи».
3. Измените ожидаемые значения и сообщения ошибок. «Не проверять это поле» исключает ожидание.
4. Нажмите «Сохранить сценарий для ученика» → «Перейти к тренировке».
5. В новой форме заполните поля в любом порядке. Неправильное подтверждённое значение вызывает Taiga Alert.
   Исправьте значение и выйдите из поля; после выполнения обязательных ожиданий перейдите дальше.

Проверка запускается автоматически. Ученик не управляет записью. Перезагрузка `/learn` начинает новую попытку.
Задание завершается на последнем записанном экране, когда выполнены его обязательные ожидания.
Неверный переход не продвигает сценарий; вернитесь на ожидаемый экран. Неоднозначные/нечитаемые поля
блокируют проверку без обвинения ученика. До blur ошибку Input/Select/ComboBox не показываем.

Редактор берёт последнее подтверждённое значение каждого поля в рамках посещения экрана. Пока поддерживается
записанный путь экранов; произвольные разрешённые ветки и группы выбора требуют следующего расширения.
Неполная запись, в том числе неподтверждённый закрытый ComboBox, не публикуется молча как сценарий.
Ранее сохранённый сценарий остаётся активным, пока админ явно не сохранит новый. Новые scans не меняют настройки.

### Проверка экранов

Откройте `/record` («Запись» в меню). На первом экране — три поля: Input, Select
и ComboBox с поиском. Checkbox/radio и числовое поле доступны на следующем экране. Заполняйте их в любом порядке:
справа карточки показывают подтверждённые значения Input, Select и ComboBox после выхода из поля (blur). «Показать в форме» подсвечивает контрол.
«Далее» открывает следующий экран, «Назад» возвращает с сохранением ответов,
«Неправильный переход» открывает отдельную ветку с возможностью возврата.
После трёх экранов заполнения появляется результат. Схемы загружаются по HTTP из статического
fixture; ответы хранятся только до ухода со страницы. Это demo приложения, не backend библиотеки.

Карточки наблюдения показывают состояние формы. После завершения записи настройки ожидаемых значений
и сообщений доступны в разделе «Настроить тренировку». Объединение radio/checkbox в карточки наборов
ещё не реализовано. Подтверждение после blur сравнивается с ожиданием только в режиме ученика.
До первого blur карточка показывает «Ожидает выхода из поля», при повторном редактировании сохраняет
предыдущее подтверждение. Очистка поля тоже подтверждается после blur.

`readScreenState(snapshot, controls, options)` читает ключ экрана из существующего атрибута
или прямого текста выбранного корня. `ScreenVisitTracker` считает посещения готовых экранов,
отличая возврат от замены DOM. [Архитектура и ограничения](ARCHITECTURE.md).

## API библиотеки

В Angular injection context:

```ts
import {inject} from '@angular/core';
import {TrainingObserver} from '@training-observer/core';

const observer = inject(TrainingObserver);

// Вызвать в браузере, когда нужный DOM уже отрисован.
const snapshot = observer.start(); // document.body по умолчанию
// observer.start(element, {batchDelayMs: 50, propertyCheckIntervalMs: 500, maxNodes: 5000});
// observer.capture(element); — ручной снимок
// observer.snapshot() — последний снимок
// observer.controls() — потенциальные контролы, в том числе disabled/hidden
// observer.isObserving() — статус сессии
// observer.stop() — остановить, сохранив последний снимок
// observer.clear() — остановить и освободить последний снимок
// observer.error() — ошибка фонового обновления
// observer.scanCount() / observer.revision() — пересчёты / публикации
```

Параметры снимка задаются через `DOM_SNAPSHOT_OPTIONS`, параметры наблюдения —
через `DOM_OBSERVATION_OPTIONS`. Настройки `start()` объединяются с defaults.
Интервал `propertyCheckIntervalMs: 0` отключает сверку native-свойств без событий.

Для привязки к жизни встраиваемого компонента укажите `providers: [TrainingObserver]`
в нём: `DestroyRef` освободит ресурсы при уничтожении этого компонента.
Корневой экземпляр сервиса живёт до уничтожения всего приложения.
Собственный интерфейс наблюдателя можно исключить селектором
`[data-training-observer-ignore]`. На чужих контролах атрибуты не требуются.

Снимок: `nodes` по ID, `rootId`, `interactiveIds`, время обхода и статистика лимитов.
ID стабилен только для того же живого DOM-узла в рамках экземпляра сервиса.
`path` — структурный путь для диагностики, не локатор между сессиями.

Текущие ограничения: light DOM одного документа, полные пересчёты, приблизительные
подписи/интерактивность/видимость. iframe и открытые shadow roots отмечаются как
необойдённые границы. `observer.logicalControls()` нормализует текстовые поля,
числовые поля, кнопки, checkbox, radio, switch, select и combobox, включая адаптеры Taiga UI.
Связанные dropdown вне формы включаются в снимок через `aria-controls`.
Остальные типы доступны в DOM-снимке.
Подсветка уже реализована. Запись учебных состояний реализована; базовый редактор и проверка ученика подключены. Автоматические
обновления объединяются, поэтому снимки не заменяют последовательность действий.
Обычная прокрутка не запускает пересчёт; служебные ползунки Taiga UI (`tui-scroll-controls`)
исключены из снимка и наблюдения. Изменения DOM при виртуализации или подгрузке
продолжают отслеживаться. Геометрия соответствует последнему снимку; при необходимости
её можно актуализировать ручным `capture()`.
Декоративные hover-переходы цветов и теней не запускают пересчёт. Появление меню,
изменение видимости и другие изменения состояния при наведении продолжают отслеживаться.

## Проверки

```sh
npm run build
npm run test:unit
npm test
npm run test:load
```

Сборка: `dist/demo/browser`, `dist/training-observer`.
Отдельная сборка библиотеки: `npx nx build training-observer`.
Граф проектов: `npm run graph`.

Браузерные тесты Playwright используют установленный **Google Chrome** (`channel: chrome`)
и автоматически запускают demo на порту 4301. Проверяют граф снимка, текущие значения,
disabled/hidden/inert, перекрытия, динамическую замену узлов, редактирование пароля,
границы обхода и лимиты. Дополнительно проверяют автообновление, объединение событий,
сверку свойств, исключение инспектора, остановку, повторный запуск и DestroyRef.
При отсутствии Chrome установите его перед запуском тестов.

`observer.confirmedControls()` — последние снимки Input/Number/Select/ComboBox, подтверждённые
выходом фокуса из логического контрола. Внутренний фокус и связанный popup не завершают редактирование.
Ключи относятся к DOM-экземплярам; `start()` и `clear()` сбрасывают подтверждения.
`logicalControls()` и диагностический DOM остаются живыми, без ожидания blur.

## Удаление строк записи

На `/record` завершите запись и нажмите «Удалить» у ненужной строки журнала.
«Отменить удаление» восстанавливает предыдущую версию; история отмены живёт до перезагрузки
или новой записи. Сам отредактированный журнал сохраняется после перезагрузки.

В разделе «Настроить тренировку» нажмите «Создать ожидания из записи» повторно.
Последнее оставшееся подтверждение становится ожидаемым значением. Авторские значения и сообщения
текущего черновика сохраняются для тех же полей. Ранее загруженный опубликованный сценарий при
пересоздании заменяется новым черновиком. Для изменения тренировки нажмите «Сохранить сценарий для ученика».
Удаление само по себе не меняет опубликованную тренировку, в том числе после перезагрузки.

Удаление границы экрана при оставшихся полях блокирует публикацию: отмените удаление или удалите
связанные строки. Общий пропуск наблюдения нельзя удалить — неизвестно, какие действия были пропущены.

## ComboBox: сравнение текста после blur

По согласованному правилу ComboBox записывается и проверяется по видимому тексту после выхода
фокуса. Выбор из списка и ручной ввод одинакового текста равнозначны для тренировки.
Пока фокус внутри поля, новое значение не засчитывается и сообщение об ошибке не появляется.
Карточка показывает подтверждённый текст; отсутствие `aria-selected` больше не создаёт пропуск записи.

Диагностический `choice.selection` по-прежнему описывает только доказанный выбор и может быть unknown.
Учебный формат сохраняет текст как массив из одной строки (пустое поле — пустой массив), как и ранее
сохранённые подписи вариантов. Это не доказательство выбора конкретной опции или её backend ID.
Предыдущие замечания о блокировке первого выбора ComboBox относятся к старому правилу; для текущего
MVP дополнительный источник подтверждения выбора не требуется. Старые строки «не удалось прочитать»
не исправляются автоматически: нужно заново записать значение либо явно удалить ненужную строку.
